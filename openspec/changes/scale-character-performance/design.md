# Design

## Context

동기는 [proposal.md](proposal.md)에, 책임을 나누는 결정과 이유는 [ADR 0006](../../../docs/adr/0006-캐릭터의-상태-포즈-표현-성능-정책을-나누어-소유한다.md)에 있다. 이 문서는 그 결정을 어떻게 옮기는지를 다룬다.

2026-11-27에 확인한 상태다.

- 자산: 두발 기린은 삼각형 15,416개·재질 6개(드로우 6회)·관절 25개·동작 채널 75개다. 착용물을 든 네발 기린은 53,872개·23회이고 1536² 이미지 두 장을 쓴다. 공개 월드 표본은 345,763개·21회다.
- 캐릭터 레이어(`web/studio-characters.js`)는 `instantiateModelsToScene`으로 캐릭터마다 메시와 골격을 복제한다. 제자리 동작은 `AnimationGroup`으로, 경로는 시간표(`shared/character-route.mjs`)의 값을 관절에 직접 써서 재생한다. 경로의 시계는 움직일 수 있는 동안에만 흐른다.
- 관람 장면(`web/scene.js`)은 직교 투영이다. 이 변경 전에는 기준 방위각에서 ±30°, 수직축 기준 20°~75° 안에서 돌았고 화면 이동은 꺼져 있었다(`panningSensibility = 0`). 전체 보기는 불러온 월드 범위에 맞춘다(`overviewWidth`). 배포 월드에서 계산하면 세로 휴대폰은 1m가 약 6.4픽셀, 1080p 화면은 약 26픽셀이다.
- 장면은 조작이 없으면 그리기를 쉬고, `keepDrawing(fn)`에 등록한 함수 하나가 참인 동안 계속 그린다. 나중에 등록한 함수가 앞의 것을 덮어쓴다.
- 실제 기기의 프레임 시간은 재지 않았다. 대표 기기는 `preserve-world-layout`의 작업 4.4가 정한다.

### 기준값 (2026-11-27, 변경 전)

`npm run bench:characters -- --measure`로 쟀다. 배경은 배포 사이트의 공개 월드(`328fc92a`, 방 7개, 삼각형 345,763개)이고, 기린은 저장소의 기본 두발 35마리·네발 15마리다. 이 파일들은 `origin/main`의 것과 해시가 같다. 배포 사이트의 공개본에는 캐릭터가 아직 없어, 배치는 기준 장면이 방마다 고르게 만든다. 코드는 `origin/main`을 합친 `claude/merge-origin-main`(`2f84516`)에 측정 도구만 더한 것으로, 전체 보기 구도가 배포 화면과 같다. 컴퓨터는 Apple M1 Pro, Chrome이고 조건마다 한 번씩 쟀다.

| 1440×900                     | 전체 보기 | 17.2ms     | 1,172  | 3,247,718 | 24 / 50         |

4번 작업(화면에 보이는 캐릭터만 움직이기, 굴절 배경에서 캐릭터 빼기) 뒤에 같은 컴퓨터에서 한 번씩 다시 쟀다(2026-11-28). 50마리가 모두 움직이는데도 드로우와 삼각형이 절반으로 줄었다. 느리게 한 조건의 전체 보기는 33.1ms로 예산 33ms에 걸쳐 있다.

| 조건                         | 구도      | 95백분위 | 드로우 | 삼각형    | 움직이는 캐릭터 |
| ---------------------------- | --------- | -------- | ------ | --------- | --------------- |
| 1440×900                     | 전체 보기 | 17.5ms   | 587    | 1,590,821 | 50 / 50         |

- 감속하지 않은 값은 화면 주사율(16.7ms)에 걸려 한계를 보여 주지 않는다. CPU를 4배 느리게 하면 50마리 중 8마리만 움직이는데도 33ms를 넘는다. 이 조건은 휴대폰을 대신하지 않으며 같은 컴퓨터에서 전후를 비교하는 데만 쓴다. **휴대폰 실측은 아직 없다.**
- 합치기 전 코드(이전 월드에 맞춘 고정 구도, 월드가 화면에 작게 보임)에서는 같은 감속 조건이 전체 보기 48.6ms, 운동회 38.7ms였다. 드로우와 삼각형 수는 같았다. 한 번씩 잰 값이라 차이가 구도 때문인지 측정 편차인지는 가리지 않았다.
- **장면 전체가 프레임마다 두 번 그려진다.** 드로우 1,172회는 보이는 서브메시 수의 약 2배다. 월드의 재질 하나(`Display glass`, 영사기 렌즈와 진열장 유리 4개 메시)가 glTF 투과(`KHR_materials_transmission`)를 쓰고, Babylon이 그 굴절 배경을 만들려고 불투명한 메시 전부를 1024² 텍스처에 한 번 더 그린다. 캐릭터 50마리도 여기에 포함된다.

## Goals / Non-Goals

**Goals:**

- 캐릭터 코드를 ADR 0006의 다섯 책임으로 나누고, 성능 수치와 판단을 정책 한 모듈에 모은다.
- 화면에 보이는 캐릭터만 자세를 계산하고, 화면 크기에 맞는 축소 단계를 그려 50마리 기준 장면이 예산 안에 들게 한다.
- 예산을 같은 조건으로 다시 잴 수 있게 기준 장면과 측정 표시를 저장소에 둔다.

**Non-Goals:**

- 인스턴스 스키닝(모든 캐릭터의 관절 행렬을 텍스처 한 장에 쓰고 모델·재질마다 한 번에 그리기). 6번 작업의 재측정이 예산을 넘으면 별도 변경으로 한다. 표현 모듈의 경계가 이 교체를 받도록 만든다.
- 자세 갱신 주기를 낮추기. 보이는 캐릭터는 그리는 프레임마다 갱신하기로 했다.
- 정적 배경 캐시, 관람용 월드에서 안 보이는 면 지우기, 착용물을 별도 자료실 자산으로 나누기, 동작 파일 다시 표본 뽑기, 점토 변형을 관람 화면에 반영하기.
- 제자리 동작(`AnimationGroup`)과 경로 재생을 하나의 재생기로 합치기.
- 서버가 축소 단계를 자동으로 만들기.

## Decisions

### 모듈 배치

`web/characters/` 아래에 둔다. 밖에서는 `index.js`만 가져온다.

| 파일        | 책임                                                                                          | 지금 있는 곳                                                 |
| ----------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `assets.js` | 모델·동작 파일을 읽고 보관하고 해제한다. 축소 단계와 착용물 노드를 찾는다                     | `model()`, `motionFile()`, `setLibrary()`                    |
| `cast.js`   | 캐릭터마다의 자리·방향·시계·동작 선택. Babylon 메시를 다루지 않는다                           | `walk()`, `play()`의 상태, `rehearse()`, `characterMotion()` |
| `pose.js`   | 클립 표본·섞기를 관절 값으로 쓴다. 체형(`giraffe-proportions.js`)과 걸음 길이 재기를 포함한다 | `pose()`, `clipTracks()`, `measureStride()`                  |
| `view.js`   | 복제해 세우기, 축소 단계 바꾸기, 착용물, 그림자, 자리 표시, 고르기 등록                       | `spawn()`, `release()`, `shadowDisc()`                       |
| `policy.js` | 화면에 보이는지, 어느 축소 단계인지. 수치를 모두 가진다                                       | `visitor-characters.js`의 `overviewLimit`, `setActive()`     |
| `index.js`  | 위를 조립한 `characterLayer()`                                                                | `characterLayer()`                                           |

`characterLayer(world, options)`가 돌려주는 모양은 유지하고 `setActive`만 없앤다(관람 화면만 썼다). `options.policy`로 정책을 받는다. 스튜디오는 축소 단계를 쓰지 않는 정책을, 관람 화면은 축소 단계를 쓰는 정책을 넘긴다.

`web/visitor-characters.js`는 관람 전용 연결(공개 파일 주소, 눌러서 페이지 열기)만 남긴다.

대안인 "지금 파일 안에서 구역만 나누기"는 옮기는 일이 없어 안전하지만, 상태와 표현이 같은 `entry` 객체를 계속 함께 고쳐 경계를 검사할 방법이 없다.

### 옮기기와 동작 변경을 나눈다

3번 작업(구조 분리)은 동작을 바꾸지 않는다. `npm test`와 `npm run test:browser`가 고치지 않은 채 통과하는 것이 완료 조건이다. 움직임 제한을 없애는 일과 축소 단계는 그 뒤 작업에서 한다. 한 커밋에 섞으면 회귀가 옮기다 생겼는지 규칙을 바꿔 생겼는지 가릴 수 없다.

### 장면 그리기 요구를 여럿이 등록한다

`world.keepDrawing(fn)`이 등록을 쌓고 해제 함수를 돌려주게 한다. 하나라도 참이면 그린다. 지금 등록하는 곳은 캐릭터 레이어 하나뿐이라 문제가 드러나지 않았지만, 움직이는 것이 하나 더 등록하면 앞의 등록을 조용히 덮어쓴다.

### 관람 카메라

관람 장면과 배치 미리보기에서 `ArcRotateCamera`의 입력을 붙이지 않는다. 방위각과 고도는 기준 구도(45°, `π/2 − 0.62`)에 고정한다. `setTarget()`은 대상을 바꿀 때 카메라 자리에서 각도를 다시 구하므로, 회전 입력을 떼는 것만으로는 방을 바꿀 때 방향이 달라진다. 그래서 각도의 상한과 하한을 같은 값으로 둔다. 화면 이동은 확대(`magnify`)가 이미 쓰는 방식과 같이, 포인터가 움직인 화면 거리를 뷰 행렬의 역으로 바꿔 `camera.target`에 더한다. 직교 투영이라 포인터 아래의 바닥이 정확히 포인터를 따라온다.

이동 범위는 전체 보기의 구도를 정하는 월드 범위(`scene.getWorldExtends()`)의 바닥 사각형이다. 화면 가운데가 보는 바닥 점, 곧 `camera.target`을 보는 방향으로 바닥 평면에 내린 점이 그 사각형 안에 머물게 자른다. 이동·확대·방 전환이 모두 같은 함수(`keepInWorld`)를 거친다. 방마다의 바닥 범위(`roomBounds`) 대신 월드 범위를 쓴 것은 전체 보기가 같은 범위로 구도를 잡아, 화면에 보이는 것과 이동 한계가 어긋나지 않기 때문이다. 전체 보기의 중심이 닿는 바닥 점은 범위에 항상 포함한다.

누르기와 끌기의 구분(6픽셀)은 지금의 `onpointerup` 판정을 그대로 쓴다. 6픽셀을 넘기 전에는 화면을 옮기지 않아, 누르기가 화면을 밀지 않는다. 두 손가락 조작은 지금처럼 확대만 한다.

대안인 "회전 범위를 0으로 좁히기"는 입력이 남아 관성 값이 장면을 계속 그리게 하고, 한 손가락 끌기를 이동에 쓸 수 없어 택하지 않았다.

### 화면에 보이는지 정하기

정책이 캐릭터의 자리를 카메라 공간으로 옮겨 직교 화면의 사각형과 비교한다. 여유는 캐릭터의 키(모델 기본 키 × 크기)다. 걸으며 팔다리가 벗어나는 폭을 덮고, 화면 가장자리에서 멈춘 자세가 먼저 보이는 일을 막는다. Babylon의 절두체 판정은 그리기만 거르고 동작 평가는 거르지 않으므로 따로 둔다.

- 보이는 캐릭터: 경로는 그리는 프레임마다 `pose()`를 쓰고, 제자리 동작은 `AnimationGroup`을 재생한다.
- 보이지 않는 캐릭터: 경로는 자리만 구하고(`routeAt`의 `x`·`z`) 관절 값은 쓰지 않는다. 제자리 동작은 그룹을 멈춘다.

스튜디오도 같은 판정을 쓴다. 회전하는 직교 카메라에서도 같은 계산이 맞는다. 다만 선택해 리허설하는 캐릭터는 항상 보이는 것으로 본다.

### 경로의 시계

경로의 시계를 프레임마다 더하는 대신 레이어의 시각에서 구한다. `시계 = 시작 시점 × 한 바퀴 길이 + (지금 − 레이어가 시작한 때)`이다. 시간표가 순수 함수라, 그리기를 쉬었다 깨어나도 그 시각의 자리와 자세가 바로 나온다. 스튜디오의 리허설(선택한 캐릭터가 처음부터 걷기)은 그 캐릭터만 따로 시작한 때를 가진다.

이로써 `walk-character-routes`의 "움직일 때만 흐르는 시계" 결정을 대체한다. 그 결정은 움직임 제한으로 멈춘 캐릭터가 **보이는 채로** 순간 이동하는 것을 막으려던 것이다. 이제 보이는 캐릭터는 멈추지 않으므로 그 문제가 없다. 탭을 숨겼다 돌아오면 캐릭터가 다른 자리에 있지만, 숨겨진 동안 일어난 일이라 받아들인다.

### 쉬는 장면에 걸어 들어오는 캐릭터

장면이 쉬는 동안에도 렌더 루프의 콜백은 돈다. 정책이 초당 4번 경로 캐릭터의 자리만 구해, 하나라도 화면에 들어오면 그리기 요구가 참이 된다. 자세 계산이 없어 50마리에서도 `routeAt` 200번/초다.

### 축소 단계

**모델 파일의 규약으로 둔다.** 착용물 규약(`Wear.` 접두사 또는 사용자 속성 `wearable`)과 같은 방식이다.

- 노드 이름 `LOD1.<원본 노드 이름>`·`LOD2.<원본 노드 이름>`, 또는 사용자 속성 `lod`(1·2)와 `lodOf`(원본 노드 이름).
- 축소 단계는 원본과 같은 골격에 묶인다. 그래서 동작·경로·체형이 따로 손대지 않아도 적용된다.
- 착용물의 축소 단계는 `LOD1.Wear.cape`처럼 착용물 노드를 가리킨다. 없으면 착용물은 원본을 쓴다.
- 합친 메시 하나가 여러 노드를 대신하면 사용자 속성 `lodCovers`에 나머지 노드 이름을 적는다. 네발 기린은 몸이 귀·눈·뿔 등 노드 20개로 나뉘어 있어, 이 속성 없이는 합친 메시를 그려도 나머지 노드가 함께 그려진다.
- 얼굴 보호 속성(`_CLAY_PROTECT`)은 축소 단계에도 내보낸다.

`shared/character-library.mjs`의 `modelFacts()`가 착용물처럼 축소 단계를 읽어 `lods: [{ level, of, node }]`로 기록하고, `shared/character-sheet.mjs`가 공개 목록에 싣는다. 클라우드와 로컬 자료실이 이 함수를 함께 쓰므로 서버 코드는 항목을 저장하고 내주는 부분만 바뀐다.

기본 기린의 목표는 1단계가 원본의 약 20%(두발 약 3,000개), 2단계가 약 4%(약 600개)다. 두 단계 모두 색을 이미지 한 장에 구워 재질 하나, 드로우 한 번으로 만든다. 새 스크립트 `scripts/character-lods.py`가 Blender 원본을 받아 줄이기와 굽기를 하고 축소 단계를 원본에 더한다. `scripts/clay-protect-attribute.py`처럼 모델 경로를 받는 일반 도구로 두어 두발·네발 기린과 이후 모델에 같이 쓴다. 네발 기린은 내보내기 스크립트가 없으므로 Blender에서 지금 방식대로 내보낸다.

대안인 "올릴 때 서버가 자동으로 줄이기"는 운영자가 할 일이 없지만, 스키닝된 메시를 `meshoptimizer`로 줄였을 때 관절 가중치와 얼굴이 쓸 만한지 확인하지 못했다. 클라우드 자료실은 Cloudflare 함수에서 돌아 무거운 처리를 넣기도 어렵다. 규약이 먼저 있으면 자동 생성은 나중에 같은 규약으로 채우는 도구가 된다.

**단계는 확대 배율 하나로 정한다.** 직교 투영이라 모든 캐릭터의 화면 크기가 같다. 정책이 `1m당 픽셀 수 = 캔버스 높이 ÷ (2 × orthoTop)`으로 장면 전체의 단계를 정한다.

| 1m당 픽셀 | 단계  | 해당하는 화면                                  |
| --------- | ----- | ---------------------------------------------- |
| 8 미만    | 2단계 | 휴대폰 전체 보기(6.4)                          |
| 8~30      | 1단계 | 휴대폰에서 방 고르기(8.7), 1080p 전체 보기(26) |
| 30 이상   | 원본  | 1080p에서 방 고르기(33), 그보다 확대           |

경계는 처음 값이고 6번 작업에서 조정한다. 확대 중에 단계가 오락가락하지 않게 경계의 10% 안에서는 지금 단계를 유지한다. 캐릭터의 크기 배율은 보지 않는다. 캐릭터마다 단계가 달라지면 같은 화면에서 품질이 섞여 보인다.

표현은 캐릭터를 세울 때 모든 단계의 메시를 함께 복제하고 `setEnabled`로 하나만 켠다. 복제는 지오메트리를 공유하므로 메모리는 단계 수가 아니라 모델 수에 비례한다. 점토 표면 셰이더의 기준 공간(`includeClayGiraffe`)은 원본 메시의 범위로 구해 모든 단계에 같이 넘긴다.

### 굴절 배경에서 캐릭터를 뺀다

Babylon의 투과 도우미가 만드는 굴절 배경 텍스처(`opaqueSceneTexture`)의 그릴 목록에서 캐릭터 메시를 뺀다. 그 텍스처는 진열장 유리와 영사기 렌즈 뒤에 비칠 장면이라, 캐릭터가 빠져도 유리 바로 뒤에 선 캐릭터가 유리 너머로 안 보이는 것 말고는 달라지지 않는다. 캐릭터 드로우가 절반이 된다.

이 텍스처는 캐릭터가 아니라 월드 재질의 것이므로 `web/scene.js`가 소유한다. 표현 모듈은 캐릭터 메시를 `world`에 "굴절 배경에 넣지 않을 메시"로 등록만 한다. 캐릭터가 빠진 뒤에는 방과 가구만 남으므로, 카메라가 멈춰 있는 동안 이 텍스처를 다시 그리지 않게 한다(`refreshRate`).

대안인 "공개용 모델에서 투과를 빼고 반투명으로 바꾸기"는 추가 그리기를 완전히 없애지만 유리의 모습이 바뀌고 굽기 파이프라인을 고쳐야 한다. 먼저 캐릭터만 빼고, 6번 작업의 재측정에서 남은 비용을 본다.

### 그림자 원판

그림자 원판 50개를 thin instance로 묶어 드로우 한 번으로 그린다. 골격이 없고 재질을 이미 공유한다. 표현 모듈이 소유한다.

### 기준 장면과 측정

- `tests/character-bench.mjs`가 임시 데이터 폴더에 캐릭터 50마리(두발 35·네발 15, 경로와 제자리 동작, 착용물을 섞어 방마다 나눠 놓음)를 둔 초안을 만들어 공개한다. 배경은 `--from <주소>`로 준 사이트의 공개 월드다. 관람객이 읽을 수 있는 것(방, 가구 배치, 구운 공개용 모델)만 가져오므로 편집 키가 필요 없다. 주소를 주지 않으면 `tests/browser.mjs`와 같은 준비한 월드를 써서 네트워크 없이 돈다. 캐릭터 자리는 공개용 모델에서 읽은 각 방의 바닥 범위 안에 고르게 둔다.
- 관람 화면은 주소에 `?perf`가 있으면 구석에 프레임 시간의 95백분위(최근 300프레임), 드로우 횟수, 그린 삼각형 수, 자세를 계산한 캐릭터 수와 축소 단계를 보여 준다. 이 표시는 따로 불러오는 모듈로 두어 평소 관람 화면의 용량을 늘리지 않는다.
- `npm run bench:characters`가 배포 사이트의 공개 월드를 배경으로 기준 장면을 같은 네트워크의 휴대폰이 열 수 있게 띄운다. 실기기의 프레임 시간은 사람이 재고, 값을 이 문서에 적는다. `-- --measure`는 이 컴퓨터의 Chrome에서 1440×900, Pixel 7 크기, Pixel 7 크기에 CPU 4배 감속의 세 조건으로 읽는다.
- `tests/browser.mjs`는 준비한 월드를 배경으로 한 기준 장면의 전체 보기를 `Pixel 7` 기기 설정으로 열어 `?perf`의 드로우 횟수와 삼각형 수를 상한과 비교한다. 자동 검사가 프레임 시간을 보지 않는 것은 검사 기기의 성능이 휴대폰을 대신하지 못하기 때문이다. 상한은 6번 작업의 측정값에 10% 여유를 둔다.

## Risks / Trade-offs

- [굴절 배경에서 캐릭터를 빼면 진열장 유리 너머로 캐릭터가 비치지 않는다] → 유리 4장 뒤에 캐릭터가 서는 경우만 해당하고, 유리는 여전히 방과 가구를 비춘다. 받아들인다.
- [복제 방식으로 그리는 한 드로우는 여전히 보이는 캐릭터 수에 비례한다. 매 프레임 갱신과 함께 50마리가 예산을 넘을 수 있다] → 6번 작업에서 재고, 넘으면 인스턴스 스키닝을 별도 변경으로 한다. 그 사이 완화가 필요하면 정책에 기기별 한도를 다시 넣을 수 있으나 명세를 바꾸는 일이다.
- [확대하는 중에 축소 단계가 바뀌는 순간이 눈에 띌 수 있다] → 경계에 여유를 두고, 축소 단계가 원본의 윤곽(목·귀·꼬리)을 지키도록 만든다. 기준 장면에서 경계를 넘나들며 눈으로 확인한다.
- [한 손가락 끌기가 이동이 되면서 회전으로 방 안쪽을 들여다보던 방법이 없어진다] → 가려지는 자리는 방 구성과 클릭 영역 배치로 푼다. 제안이 정한 바다.
- [방을 고르면 그 방만 움직이던 연출이 사라진다] → 옆방이 화면에 보이면 함께 움직인다.
- [탭을 숨겼다 돌아오면 경로 캐릭터가 다른 자리에 있다] → 받아들인다.
- [구조를 옮기다 편집 장면이 깨질 수 있다] → 3번 작업은 동작을 바꾸지 않고 기존 검사 통과를 조건으로 한다.
- [운영 자료실의 모델에는 축소 단계가 없다] → 없는 모델은 원본으로 그리므로 배포가 깨지지 않는다. 효과를 보려면 새 버전을 올리고 다시 공개해야 한다.

## Migration Plan

1. 카메라, 구조 분리, 정책은 코드 배포만으로 적용된다. 초안·공개본 형식이 바뀌지 않는다.
2. 축소 단계가 든 기본 기린을 저장소에 넣고 배포한다. 운영 스튜디오의 자료실에는 **새 버전 올리기**로 넣는다.
3. 다시 공개하면 공개 파일 목록에 축소 단계가 고정된다. 그 전의 공개본은 원본으로 계속 보인다.
4. 되돌릴 때는 코드 배포를 되돌린다. 축소 단계가 든 모델 파일은 이전 코드에서 축소 단계 메시가 원본과 겹쳐 보이므로, 모델도 이전 버전으로 다시 올린다.
