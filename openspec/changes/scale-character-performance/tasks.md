## 1. 기준 측정

- [x] 1.1 `tests/character-bench.mjs`가 임시 데이터 폴더에 캐릭터 50마리(두발·네발, 경로·제자리 동작·착용물을 섞음)를 둔 초안을 만들어 공개하게 한다. 관람 화면을 열어 50마리가 보이는지 확인한다. 배경을 배포 사이트의 공개 월드로 받는 `--from`을 더했고, 그 월드의 여섯 방에 50마리가 선 화면과 `?perf`의 캐릭터 수 50을 확인했다.
- [x] 1.2 관람 화면에 `?perf` 측정 표시(프레임 시간 95백분위, 드로우 횟수, 그린 삼각형 수, 자세를 계산한 캐릭터 수)를 따로 불러오는 모듈로 더한다. `npm run build` 결과에서 평소 관람 화면이 그 모듈을 불러오지 않는지 확인한다. 빌드 결과에 `perf-readout-*.js`가 따로 있고 진입 파일은 `?perf`일 때만 불러온다.
- [ ] 1.3 `npm run bench:characters`로 기준 장면을 같은 네트워크의 휴대폰에서 열 수 있게 한다. 지금 코드의 전체 보기와 방 확대 값을 휴대폰과 데스크톱에서 재서 `design.md`의 Context에 기기 이름과 함께 적는다. 명령과 데스크톱 값(M1 Pro, CPU 4배 감속 포함)은 끝났다. 휴대폰 실측이 남았다.
- [x] 1.4 이 체크아웃을 배포 코드(`origin/main`)와 합친 뒤 `npm run bench:characters -- --measure`를 다시 돌려 `design.md`의 기준값을 배포 구도의 값으로 바꾼다. `origin/main`을 합친 `claude/merge-origin-main`(`2f84516`)에서 다시 재서 기준값을 바꿨다. `main`도 그 커밋으로 옮겼다.

## 3. 구조 분리

- [ ] 3.5 `web/giraffe-proportions.js`를 `web/characters/`로 옮기고 `tests/clay-character.test.mjs`의 가져오기를 고친다. 지금은 `pose.js`가 제자리의 파일을 다시 내보낸다. 이 파일과 그 검사에 다른 작업의 커밋 안 된 변경이 있어 3.2에서 옮기지 않았다.
- [x] 3.3 움직임 제한(`setActive`, `overviewLimit`)을 `web/characters/policy.js`로 옮기고 `characterLayer()`가 `options.policy`를 받게 한다. 이 단계에서는 지금 규칙(방, 8개·24개)을 그대로 낸다. 같은 검사가 통과하는지 확인한다.
- [x] 3.4 `web/AGENTS.md`의 스튜디오 규칙에 캐릭터 모듈의 경계(밖에서는 `characters/index.js`만 가져온다, 수치는 `policy.js`에만 둔다)를 더하고, `tests/`에 `web/characters/` 밖의 파일이 그 안의 다른 파일을 가져오면 실패하는 검사를 더한다.

## 4. 성능 정책

- [x] 4.1 경로의 시계를 레이어의 시각에서 구하게 바꾼다(리허설은 따로 시작한 때를 가진다). 그리기를 쉬었다 깨어난 뒤의 자리가 흐른 시간과 맞는지 `npm test`의 경로 검사로 확인한다. 시계는 `cast.js`가 시각에서 구한다. 경로 검사 대신 가짜 시계를 쓰는 `tests/character-cast.test.mjs`에서, 사이 프레임 없이 같은 시각에 같은 자리가 나오는 것을 확인했다.
- [x] 4.2 정책이 캐릭터가 화면에 보이는지 정하고, 보이지 않는 캐릭터는 자세를 쓰지 않으며(경로) 그룹을 멈추게(제자리 동작) 한다. 터치 기기 8개·그 밖 24개 한도와 방 기준 제한을 없앤다. 기준 장면에서 방 하나를 확대했을 때 `?perf`의 자세를 계산한 캐릭터 수가 화면에 보이는 수와 같은지 확인한다. 실행 중인 로컬 사이트에서 캐릭터를 화면 밖으로 옮기면 `?perf`의 값이 0, 되돌리면 1이 되는 것을 확인했다. 기준 장면의 방 확대는 50마리가 모두 화면 여유 안에 들어 50으로 나온다.
- [x] 4.3 장면이 쉬는 동안 초당 4번 경로 캐릭터의 자리를 확인해, 화면에 들어오면 그리기를 다시 시작하게 한다. `tests/browser.mjs`에 가만히 둔 화면으로 캐릭터가 걸어 들어오는 검사와 화면 밖에서 흐른 시간만큼 나아간 자리에 있는 검사를 더해 통과시킨다. 브라우저 검사 대신 `tests/character-cast.test.mjs`가 가짜 시계와 가짜 화면 판정으로 두 경우를 확인한다. 실제 화면에서 걸어 들어오는 모습은 보지 않았다.
- [x] 4.4 `show-characters-to-visitors`의 "관람 장면의 움직임 제한" 요구사항과 `walk-character-routes`의 "움직임 제한에서 멈추는 캐릭터는…" 문장을 지우고 두 변경의 `openspec validate`를 통과시킨다. `docs/world/README.md` 캐릭터 항목의 움직임 제한 설명을 고친다.
- [x] 4.5 굴절 배경 텍스처의 그릴 목록에서 캐릭터 메시를 빼고, 카메라가 멈춰 있는 동안 그 텍스처를 다시 그리지 않게 한다(`web/scene.js` 소유, 표현 모듈은 메시를 등록만 한다). 기준 장면의 드로우 횟수가 캐릭터 몫만큼 줄었는지 `?perf` 값으로, 진열장 유리가 방과 가구를 여전히 비추는지 화면으로 확인한다. 드로우가 1,172에서 587로 줄었다. 진열장 유리의 모습은 화면으로 비교하지 않았다.

## 5. 축소 단계

- [x] 5.1 `shared/character-library.mjs`의 `modelFacts()`가 축소 단계(`LOD1.`·`LOD2.` 이름 또는 `lod`·`lodOf` 속성)를 읽어 `lods`로 기록하고, 짝이 없는 단계는 빼고 알림에 싣게 한다. `shared/character-sheet.mjs`가 공개 목록에 싣는다. 축소 단계가 없는 기존 항목이 그대로 읽히는지와 함께 `npm test`로 확인한다. 검사는 `tests/character-lods.test.mjs`에 두었다. 알림은 모델 항목의 `lodOrphans`로 기록한다.
- [ ] 5.2 자료실의 모델 설정에 축소 단계 수와 짝 없는 단계 알림을 기존 디자인 시스템 컴포넌트로 보인다. `tests/browser.mjs`에서 축소 단계가 든 모델을 올려 표시를 확인한다. 모델 설정의 **구성**에 표시를 더했다. 축소 단계가 든 모델을 올려 보는 `tests/browser.mjs` 검사는 아직 없다.
- [x] 5.3 `view.js`가 모든 단계의 메시를 함께 복제해 하나만 켜고, `policy.js`가 1m당 픽셀 수로 장면 전체의 단계를 정하게 한다(경계 여유 10%, 스튜디오 정책은 항상 원본). 점토 표면의 기준 공간과 얼굴 보호가 모든 단계에 적용되게 한다. 기준 장면에서 확대·축소하며 단계가 바뀌어도 자리·동작·체형·착용물이 유지되는지 `tests/browser.mjs`로 확인한다. 단계 결정과 부위 선택은 `tests/character-lods.test.mjs`의 단위 검사로 확인했다. 기준 장면에서 네발 기린이 전체 보기에서는 축소 단계로, 확대하면 원본으로 케이프를 입은 채 그려지는 것을 화면으로 확인했다. `tests/browser.mjs` 검사는 그 검사의 월드에 축소 단계가 든 캐릭터가 없어 더하지 않았다.
- [ ] 5.4 모델 GLB를 받아 축소 단계를 더하는 `scripts/character-lods.mjs`(Blender 쪽은 `scripts/character-lods.py`: 합치기, 줄이기, 색을 이미지 한 장에 굽기)를 만들고, 두발·네발 기린 GLB에 축소 단계 2개를 넣는다. 각 단계의 삼각형 수와 재질 수를 검사한다. 도구를 만들어 네발 기린에 적용했고(`tests/character-lods.test.mjs`가 확인), 원본·1단계·2단계를 나란히 렌더해 모습을 비교했다. 두발 기린은 그 GLB와 내보내기 스크립트에 다른 작업의 커밋 안 된 변경이 있어 남겼다. 얼굴 보호 속성(`_CLAY_PROTECT`)을 가진 모델은 아직 다루지 않는다. 두발 기린에 적용할 때 필요하다. 착용물의 축소 단계도 만들지 않는다.
- [x] 5.5 그림자 원판을 thin instance로 묶어 드로우 한 번으로 그린다. 기준 장면의 드로우 횟수가 캐릭터 수만큼 줄었는지 `?perf` 값으로 확인한다. 드로우가 587에서 538로 줄었고, 기준 장면을 확대한 화면에서 발밑 그림자를 확인했다.
- [x] 5.6 `docs/world/README.md`의 **캐릭터 모델 만들기**에 축소 단계 규약과 내보내기 명령을 적고, 적은 명령이 그대로 실행되는지 확인한다. 규약과 명령을 적었고, 적은 명령으로 네발 기린을 만들었다.

## 6. 통합 확인

- [ ] 6.1 기준 장면을 대표 휴대폰에서 다시 재서 전체 보기와 방 확대의 프레임 시간 95백분위·드로우 횟수·삼각형 수를 1.3의 값과 나란히 `design.md`에 적는다. 축소 단계 경계에서 단계가 바뀌는 모습을 눈으로 확인하고 경계 값을 확정한다.
