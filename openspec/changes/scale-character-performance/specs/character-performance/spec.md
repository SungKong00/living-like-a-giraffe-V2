# Spec Delta

## Purpose

캐릭터 수가 늘어도 관람 화면이 정한 프레임 예산 안에서 움직이도록, 어느 캐릭터를 움직이고 얼마나 자세히 그릴지와 그 예산을 확인하는 방법을 정한다.

## ADDED Requirements

### Requirement: 화면에 보이는 캐릭터의 움직임

관람 장면은 화면에 보이는 모든 캐릭터를 그리는 프레임마다 움직여야 한다(MUST). 기기 종류나 캐릭터 수, 고른 방에 따라 보이는 캐릭터를 멈추지 않아야 한다(MUST). 움직이는 캐릭터가 화면에 하나도 없고 방문자의 조작도 없으면 장면은 그리기를 쉰다.

#### Scenario: 전체 보기의 캐릭터

- **WHEN** 방문자가 휴대폰으로 캐릭터 50마리가 놓인 월드의 전체 보기를 연다
- **THEN** 화면에 보이는 캐릭터가 모두 자기 동작이나 경로를 재생한다

#### Scenario: 방을 고른 뒤 옆방

- **WHEN** 방문자가 방을 골랐는데 화면 가장자리에 옆방의 캐릭터가 보인다
- **THEN** 고른 방과 옆방의 캐릭터가 모두 움직인다

### Requirement: 화면 밖 캐릭터

화면 밖 캐릭터는 자세를 계산하지 않아야 한다(MUST). 경로를 걷는 캐릭터는 화면 밖에서도 경로의 시간이 흘러, 다시 보일 때 그 시각의 자리와 자세로 나타나야 한다(MUST). 제자리 동작은 다시 보일 때 이어서 재생한다. 화면 가장자리에서 캐릭터가 멈춘 자세로 보였다가 움직이기 시작하지 않아야 한다(MUST).

#### Scenario: 화면 밖으로 걸어 나간 캐릭터

- **WHEN** 경로를 걷던 캐릭터가 화면 밖으로 나간 뒤 방문자가 20초 뒤에 그쪽으로 화면을 옮긴다
- **THEN** 캐릭터는 나간 자리가 아니라 경로에서 20초만큼 나아간 자리에서 걷고 있다

#### Scenario: 화면 안으로 걸어 들어오는 캐릭터

- **WHEN** 방문자가 화면을 그대로 두었는데 화면 밖에서 걷던 캐릭터의 경로가 화면 안으로 이어진다
- **THEN** 캐릭터가 걷는 자세로 화면 안으로 들어온다

### Requirement: 화면 크기에 맞는 축소 단계

모델에 축소 단계가 있으면 관람 장면은 캐릭터가 화면에 보이는 크기에 맞는 단계를 그려야 한다(MUST). 단계가 바뀌어도 캐릭터의 자리·방향·크기·체형·착용물·동작이 유지되어야 한다(MUST). 축소 단계가 없는 모델과 착용물은 모든 크기에서 원본을 그린다(MUST). 스튜디오의 편집 장면은 항상 원본을 그린다(MUST).

#### Scenario: 전체 보기와 확대

- **WHEN** 방문자가 축소 단계가 든 기린이 놓인 월드의 전체 보기에서 기린 한 마리까지 확대한다
- **THEN** 전체 보기에서는 축소 단계가, 확대한 화면에서는 원본이 보이고, 기린은 같은 자리에서 같은 동작을 이어 간다

#### Scenario: 축소 단계가 없는 모델

- **WHEN** 축소 단계 없이 올린 모델의 캐릭터가 전체 보기에 있다
- **THEN** 그 캐릭터는 원본으로 보이고 다른 캐릭터와 같이 움직인다

#### Scenario: 케이프를 입은 캐릭터

- **WHEN** 케이프를 입힌 캐릭터가 축소 단계로 보인다
- **THEN** 케이프를 입은 채로 보인다

### Requirement: 모델의 축소 단계 등록

자료실은 올린 모델 파일에서 축소 단계를 읽어 모델 항목에 기록해야 한다(MUST). 축소 단계는 원본 메시와 같은 골격에 묶이고, 이름이 `LOD1.`·`LOD2.`와 원본 노드 이름으로 이루어지거나 사용자 속성 `lod`(1 또는 2)와 `lodOf`(원본 노드 이름)를 가진 노드다. 짝이 되는 원본이 없는 축소 단계는 기록하지 않고 올린 사람에게 알려야 한다(MUST). 공개본의 파일 목록은 그 모델의 축소 단계 기록을 함께 고정해야 한다(MUST).

#### Scenario: 축소 단계가 든 모델 올리기

- **WHEN** 운영자가 몸통에 `LOD1.`·`LOD2.` 메시가 든 모델을 자료실에 올린다
- **THEN** 모델 설정에 축소 단계 2개가 표시된다

#### Scenario: 짝이 없는 축소 단계

- **WHEN** 원본에 없는 이름을 가리키는 `LOD1.` 노드가 든 모델을 올린다
- **THEN** 모델은 등록되고, 그 노드는 축소 단계로 쓰이지 않는다는 알림이 보인다

#### Scenario: 공개 뒤 모델 교체

- **WHEN** 공개본을 연 뒤 그 공개본이 쓰는 모델에 축소 단계가 다른 새 버전을 올린다
- **THEN** 관람 화면은 다시 공개하기 전까지 이전 파일과 이전 축소 단계를 쓴다

### Requirement: 성능 예산

캐릭터 50마리를 놓은 기준 장면은 대표 중급 휴대폰의 관람 화면에서 프레임 시간의 95백분위가 33ms 이하여야 한다(MUST). 측정은 전체 보기와 방 하나를 확대한 화면에서, 화면을 이동하고 확대·축소하는 동안 한다. 기준 장면과 측정 절차는 저장소에 두어 같은 조건으로 다시 잴 수 있어야 한다(MUST).

#### Scenario: 기준 장면 측정

- **WHEN** 대표 기기에서 기준 장면의 전체 보기를 열고 정한 순서로 화면을 이동·확대한다
- **THEN** 관람 화면이 프레임 시간의 95백분위와 드로우 횟수를 보여 주고, 95백분위가 33ms 이하다

### Requirement: 성능 회귀 검사

자동 검사는 기준 장면의 전체 보기에서 한 프레임의 드로우 횟수와 그린 삼각형 수가 정한 상한을 넘지 않는지 확인해야 한다(MUST). 상한을 넘으면 검사가 실패해야 한다(MUST).

#### Scenario: 축소 단계가 빠진 경우

- **WHEN** 기본 기린 모델에서 축소 단계가 빠진 채 검사를 실행한다
- **THEN** 전체 보기의 삼각형 수가 상한을 넘어 검사가 실패한다
