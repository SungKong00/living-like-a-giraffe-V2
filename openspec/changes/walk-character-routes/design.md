# Design

## Context

캐릭터는 `characters[]`에 방 기준 `position`·`yaw`와 제자리 `motion`(클립 하나, 목록 또는 null)을 가진다. 캐릭터 레이어(`web/studio-characters.js`)는 동작 파일의 클립을 노드 이름으로 복사해 `AnimationGroup`으로 재생하고, `motionPhase(id)`로 캐릭터마다 시작점을 흩뜨린다. `setActive(ids)`는 움직일 캐릭터만 재생하고 나머지는 멈춘다. 편집·관람 장면 모두 이 레이어를 쓴다. 두발 기린의 `두 발 걷기`는 제자리 보행이고, 왼발과 오른발을 한 번씩 딛는 데 1.10초가 걸린다. 방은 `rooms`의 노드이고, 방 바닥 범위는 월드 좌표의 `roomBounds`로 알 수 있다. 장면은 요청할 때만 그린다(`world.wake()`).

## Goals / Non-Goals

**Goals**

- 경로 재생을 한 모듈의 순수 함수(경로 설정 + 시각 → 자리·방향·동작 가중치)로 두어, 편집과 관람이 같은 결과를 내고 `npm test`로 검사할 수 있게 한다.
- 발이 미끄러져 보이지 않을 만큼 걸음과 이동 속도를 맞춘다.

**Non-Goals**

- 방을 넘어가는 경로, 계단·높낮이가 다른 바닥(경로 전체가 캐릭터 높이 `position[1]`을 쓴다).
- 가구·다른 캐릭터와의 충돌 회피, 자동 배회. 가구를 피하는 일은 운영자가 경로로 정한다.
- 관람객 조작, 관람객 사이의 시각 동기화.

## Decisions

### 데이터 형식

```js
route: {
  points: [                      // 2~12개. at은 캐릭터 위치 기준 [x, z], 첫 지점은 [0, 0]
    { at: [x, z] },              // 지나가기
    { at: [x, z], stop: {        // 멈추기
        face: 'next' | 각도,     // 기본 'next'
        motion: null | clip | [clip…],  // 기존 motion 형식, 기본 없음
        repeat: 1~5,             // 기본 1
        wait: 0~60,              // 초, 기본 0
    } },
  ],
  mode: 'loop' | 'pingpong',     // 기본 'loop'
  speed: 0.2~3,                  // m/s. 없으면 걸음에 맞춘 속도
  walk: clip,                    // 걷기 동작
  idle: clip | null,             // 서 있을 때, 기본 정지 자세
}
```

지점 하나에 할 일이 하나뿐이므로 "멈추기 → 동작 → 대기 → 출발"은 고정된 순서로 둔다. 한 지점의 동작을 여러 개 하려면 `motion` 목록을 쓴다. 기존 제자리 `motion` 형식을 그대로 다시 쓰므로 편집기의 동작 선택기와 서버 검증을 공유한다. 대안인 "지점마다 단계 목록(동작·대기·돌기를 자유롭게 나열)"은 요청한 순서를 모두 담지만, 편집기가 목록 안의 목록이 되어 무거워져 택하지 않았다. 필요해지면 `stop`을 단계 목록으로 넓힐 수 있다.

지점을 캐릭터 위치 기준으로 저장한다. 캐릭터를 끌거나, 방향키로 밀거나, 위치 값을 고치거나, 복제하거나, 다른 방으로 옮기는 기존 코드가 `position`만 바꿔도 경로가 모양을 지킨 채 따라온다. 1번 지점만 옮길 때(표식 끌기, 1번 지점 지우기)는 캐릭터 위치를 옮기고 나머지 지점을 그만큼 되돌린다(`web/edit-ops.js`). 대안인 "방 기준 좌표"는 위치를 바꾸는 모든 곳에서 지점을 함께 옮겨야 하고, 한 곳이라도 빠지면 경로가 조용히 찌그러져 택하지 않았다. 서버는 저장할 때 첫 지점을 `[0, 0]`으로 맞춘다.

### 시간표로 재생한다

경로를 불러올 때 구간 목록(걷기 직선·모서리 호·제자리 돌기·동작·대기)으로 펼치고 각 구간의 길이(초)를 구한다. 동작 길이는 클립을 읽은 뒤에야 알 수 있으므로, 시간표는 경로가 쓰는 클립을 모두 읽은 뒤 만든다. 그 전에는 캐릭터가 첫 지점에 서 있다. 한 바퀴 길이 `T`가 정해지면 `evaluate(timeline, t mod T)`가 자리·방향과 클립별 프레임·가중치를 돌려준다.

캐릭터마다 자기 시계 `t`를 가진다. 시작값은 `motionPhase(id) × T`다. 처음에는 움직이는 동안에만 흐르게 해, 움직임 제한으로 멈췄다가 다시 움직일 때 순간 이동하지 않게 했다. [캐릭터 성능 변경](../scale-character-performance/design.md)에서 움직임 제한을 없애면서 시계를 레이어가 시작한 뒤 흐른 시각에서 구하도록 바꿨다. 화면 밖이거나 장면이 쉬는 동안에도 경로가 흐른다. 대안인 "모두가 같은 벽시계 기준"은 관람객끼리 같은 장면을 보게 하지만 택하지 않았다.

경로 캐릭터는 `AnimationGroup`을 재생하지 않는다. 레이어가 매 프레임 시간표가 정한 클립(하나, 전환 중에는 둘)의 값을 `Animation.evaluate`로 읽어 섞은 뒤 노드에 직접 쓴다. 클립이 움직이지 않는 노드는 모델을 불러올 때 적어 둔 정지 자세와 섞는다. 시간표가 위치와 자세를 모두 정하므로 둘이 어긋나지 않고, 그리기를 쉬었다 깨어나도 같은 시각이면 같은 자세가 된다. 쓰는 시점은 장면의 애니메이션 단계 직전(`onBeforeAnimationsObservable`)이라, 체형 조절(`web/giraffe-proportions.js`)이 그 뒤에 지금처럼 값을 고친다. 대안인 "그룹을 재생하고 가중치만 조절"은 Babylon의 재생 시계와 경로 시계가 따로 흘러 동작 길이만큼 서 있는 순서를 정확히 맞추기 어려워 택하지 않았다. 경로가 없는 캐릭터는 지금의 `play()` 경로를 그대로 쓴다.

### 모서리와 돌기

- 지나가기 지점은 앞뒤 구간에 접하는 원호로 바꾼다. 반지름은 `min(0.6m × 크기, 짧은 쪽 구간 길이의 0.45배)`이다. 호 위에서도 같은 속도로 걷고, 방향은 접선을 따른다.
- 멈추기 지점과 왕복의 양 끝은 지점에 정확히 도착한다. 도는 각도가 있으면 초당 180°로 제자리에서 돌고, 그 동안 걷기 클립을 절반 빠르기로 이어 재생한다.
- 걷기 ↔ 동작·서기 전환은 새 구간의 처음 0.3초 동안 앞 구간의 마지막 자세에서 섞어 들어온다. 도착할 때 감속 곡선은 따로 두지 않는다. 같은 동작을 반복할 때는 섞지 않고 처음부터 다시 재생한다.
- 걷기 클립은 걸은 시간만큼 흐르는 시계를 읽고, 이 시계는 바퀴가 바뀌어도 이어진다. 그래서 돌아오기 경로가 한 바퀴를 마칠 때 걸음이 튀지 않는다.

### 걸음과 속도 맞추기

걸음 길이(크기 100%에서 걷기 한 주기 동안 나아가는 거리)는 장면이 걷기 클립에서 잰다. 한 주기를 48번 나눠 자세를 잡고, 높이가 변하는 관절 중 가장 낮은 것을 땅에 닿은 발로 본다. 그 발이 두 표본 사이에 뒤로 밀린 거리의 중앙값에 표본 수를 곱한다. 두발 기린의 `두 발 걷기`는 1.02m로, 파일의 발굽 궤적에서 접지 구간의 속도로 계산한 값과 같다. 처음에는 밀린 거리를 모두 더했는데, 발을 바꿔 딛는 구간이 빠져 0.89m로 13% 낮게 나와 중앙값으로 바꿨다. 움직이지 않는 관절(바닥에 놓인 루트)은 발로 보지 않는다.

걸음에 맞춘 속도는 `걸음 길이 × 크기 / 주기 길이`다. `route.speed`가 없으면 이 속도로 걷고 걷기 클립은 원래 빠르기로 재생한다. 속도를 정하면 걷기 재생 빠르기가 `speed / 걸음에 맞춘 속도`가 되고 0.5~2배로 자른다. 범위를 넘으면 편집기의 속도 행 아래에 알림을 띄운다. 자료실 모델의 `stride`는 운영자가 잰 값 대신 쓰도록 정한 값이고, 없으면 장면이 잰 값을 쓴다. 공개본의 파일 목록에도 `stride`를 실어 관람 화면이 같은 값을 쓴다.

모델은 정면(+Z, Blender의 −Y)을 보고 걷는다고 가정한다. 기본 네발·두발 기린이 그렇다.

대안인 "동작 빠르기만 정하고 이동 속도는 그 결과로 둔다"는 운영자가 지점 사이 시간을 예측하기 어려워 택하지 않았다. "서버가 올릴 때 걸음 길이를 잰다"는 서버에 골격 평가를 새로 넣어야 해서 택하지 않았다.

### 스튜디오 편집

- 캐릭터 편집기의 동작 구역 아래에 **경로** 구역을 둔다. 경로가 없으면 **경로 그리기** 단추만 보인다. 경로가 있으면 재생 단추, 반복 방식(`Segmented`), 속도(`Slider`), 걷기·서기 동작(`Select`)이 보이고, 지점마다 소제목("2번 지점 · 멈추기 · 손 흔들기 ×2 · 3초 대기")과 그 아래 행(할 일 `Segmented`와 지점 삭제 `IconButton`, 멈추기면 방향·동작·반복·대기)을 펼쳐 둔다. 맨 아래에 **지점 더하기**와 **경로 지우기**가 있다. 모두 기존 컴포넌트로 만들었고 디자인 시스템은 바꾸지 않았다. 지점을 접는 `Disclosure`는 열림 상태를 따로 기억해야 해서 쓰지 않았다.
- 장면의 경로선과 번호 표식(`web/route-guide.js`)은 조명 안내처럼 편집 장면 전용이다. 선택한 캐릭터의 경로만 보인다. 경로선은 시간표의 직선·원호를 따라 그려 실제로 도는 모서리가 보인다. 표식은 바닥에 눕힌 원판이고 숫자가 카메라 쪽에서 바로 읽히게 돈다. 멈추는 지점은 채운 표식이다. 표식은 일반 고르기 대상이 아니어서 바닥 클릭과 가구 선택을 가리지 않고, 포인터가 표식 위에 있을 때만 지점 끌기가 시작된다.
- 지점 표식을 끌면 바닥 격자(0.25m, ⌘/Ctrl로 끄기)를 따른다. 포인터가 캐릭터의 방 바닥을 벗어나면 지점은 마지막으로 유효했던 자리에 머문다.
- 그리기 모드는 기존 **포인터로 놓기**와 같은 포인터 흐름을 쓴다. 누르는 동안의 지점은 초안에 넣지 않고 미리보기로만 보이며, Enter에서 편집 한 번으로 기록한다. 12개째 지점을 찍으면 저절로 마친다.
- 경로가 있는 캐릭터를 끌어 놓거나 포인터로 놓을 때, 옮긴 경로의 지점 하나라도 놓는 방의 바닥 범위(`roomBounds`)를 벗어나면 놓기를 취소한다. Q·E 회전은 캐릭터의 처음 방향만 바꾸고 경로는 돌리지 않는다.
- 새 경로의 걷기 동작은 이름에 "걷"이나 "walk"가 든, 그 모델을 움직이는 클립으로 정한다. 없으면 캐릭터의 지금 동작, 그것도 없으면 맞는 첫 클립이다. 모델을 움직이는 동작이 하나도 없으면 경로를 만들지 않고 알린다.
- 모든 변경은 `editor`의 명령 하나로 기록해 되돌리기·자동 저장을 함께 탄다.

### 공개 파일 목록과 관람

`characterSheet()`가 동작 파일을 모을 때 `route.walk`, `route.idle`과 각 `stop.motion`도 포함한다. 관람 장면의 `visitorCharacters`는 바꾸지 않는다. 레이어가 경로를 알아서 재생하고, `setActive`는 경로 캐릭터의 시계를 멈추거나 다시 흐르게 한다. 경로 캐릭터가 움직이는 동안 장면은 계속 그려지는데, 이것은 지금의 걷는 캐릭터와 같다.

## Risks / Trade-offs

- [정지 자세가 서 있는 모양이 아닌 모델(T자세 등)] → 멈추기·서기에서 어색해진다. 편집기가 `idle`이 없는 경로에서 "서 있을 때 동작을 고르면 자연스럽다"를 안내한다. 기본 두발 기린의 정지 자세는 서 있는 모양이다.
- [걸음 길이 측정이 잘못된 모델] → 발이 미끄러진다. 자료실에서 값을 직접 정하고 잰 값으로 되돌릴 수 있다.
- [정면이 +Z가 아닌 모델] → 옆이나 뒤로 걷는다. Blender에서 −Y를 보도록 돌려 다시 내보낸다.
- [스튜디오에서 경로 캐릭터가 있으면 장면을 계속 그림] → 제자리에서 걷는 캐릭터와 같은 부담이다.
- [경로가 가구를 통과] → 막지 않는다. 경로선을 보여 운영자가 직접 피하게 한다.
- [관람 시 휴대폰 부담] → 움직이는 캐릭터 수는 기존 제한(8/24)을 그대로 쓴다. 시간표 계산은 캐릭터당 구간 수십 개에 대한 상수 시간 조회다.
- [클립을 읽기 전 시간표 길이를 모름] → 그동안 첫 지점에 서 있는다. 읽기에 실패한 동작 클립은 길이 0으로 건너뛰고, 걷기 클립이 없으면 미끄러지듯 움직이지 않도록 경로를 재생하지 않고 첫 지점에 서 있게 한다.

## Migration Plan

`route`는 선택 항목이라 기존 초안·공개본은 그대로 읽는다. 공개본별 파일 목록은 다음 공개부터 경로 동작을 포함한다. 되돌릴 때는 경로가 든 초안을 이전 코드가 거부(`strictObject`)하므로, 코드를 되돌리기 전에 경로를 지운 초안을 공개해 둔다.

## Open Questions

- 모서리 반지름 0.6m, 돌기 180°/s, 전환 0.3초는 지금 값으로 두발 기린이 걷는 것을 확인했다. 다른 모델과 동작을 올린 뒤 조정할 수 있다.
