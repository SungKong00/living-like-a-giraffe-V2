# Design

## Context

[월드 자산](../../../docs/world/README.md)의 v06 전체 원본에는 여러 장면이 있다. 기존 웹 월드는 직교 카메라와 고정 방향 (1, 1, 1)을 사용한다. 기존 웹용 GLB는 2.69 MB, 삼각형 257,632개이며 조명 추출 데이터에는 면광원 9개와 스팟 3개가 있다. V2의 성능과 화질은 별도로 측정한다.

## Goals / Non-Goals

제작자와 운영자는 현재 공간을 담은 편집 가능한 전체 .blend 하나를 주고받는다. PC 웹 편집기에서는 지정한 가구와 클릭 연결을 편집한다. 메시 분리·조형·원본 재질 제작·벽·바닥은 Blender 제작자가 맡는다. 휴대폰은 관람과 읽기 전용 결과 확인을 지원한다. 첫 버전 범위에서 이동하는 기린과 이동 경로는 제외한다. 방문자에게는 최적화된 웹 자산과 행사 페이지를 제공한다.

## Decisions

### 제작자가 파일을 줄 때

1. 전체 월드 파일과 웹으로 내보낼 장면을 지정한다. 텍스처와 링크 라이브러리를 파일 안에 패킹하고 저장한다. 단일 파일로 전달할 수 없는 필수 의존성은 가져오기 단계에서 경로를 표시해 해결한다. [Blender 리소스 패킹](https://docs.blender.org/manual/en/latest/files/blend/packed_data.html)
2. 방에는 위치와 방향의 기준점과 고유 ID를 둔다. 움직일 의자는 한 오브젝트 또는 좌판·다리를 묶은 하나의 부모에 편집 표시와 고유 ID를 부여한다. 이름이나 외형이 바뀌어도 같은 가구의 ID·원점·축을 유지한다. 복제한 가구에는 새 ID를 부여한다.
3. 첫 인계 이후에는 사이트에서 내려받은 전체 파일을 작업 출발점으로 사용한다. 파일에 남긴 인계 식별자로 다운로드 당시의 정확한 상태를 찾는다. 일반 Blender에서 열고 편집하고 저장할 수 있어야 한다.

### 월드 전체 파일 왕복

| 단계 | 담당과 결과 |
| --- | --- |
| 웹에서 편집 | 방 기준의 가구 최종 위치·회전·크기를 ID별로 저장한다. Babylon.js 편집기와 관람 모드는 같은 변환을 사용한다. 클릭 영역은 방 또는 가구 기준으로 저장하고 개요·페이지 ID·외부 링크를 연결한다. |
| 전체 다운로드 요청 | 권한을 확인하고 선택된 개정을 고정한다. 편집 화면의 기본값은 마지막으로 저장한 초안이다. 현재 발행본은 별도 다운로드로 표시한다. 초안 인계는 모바일 베이크 완료를 기다리지 않는다. 서버가 전체 원본의 복사본에서 Blender를 백그라운드로 실행해 웹 배치를 대입한다. 원본 계층·재질·조명·다른 장면을 보존한다. 좌표 변환은 방 기준, glTF 미터·오른손 Y-up을 기준으로 왕복 검증한다. |
| 전달 | 원본 제작 환경의 외부 파일에 접근할 수 없는 작업 공간에서 결과를 다시 열어 검증한 뒤 .blend 한 개를 제공한다. 같은 원본·가구 구성·배치·옵션·생성 설정의 요청은 완성본을 재사용한다. 드래그할 때마다 전체 파일을 생성할 필요가 없다. |
| 재업로드 | 다운로드 당시·현재 웹·업로드 후보 세 상태를 비교한다. 최신 웹 편집만 있으면 이를 유지하고, 제작자만 바꾼 배치는 가져온다. 양쪽의 최종값이 같으면 한 번만 반영한다. 같은 가구를 서로 다르게 옮겼으면 가구별로 두 위치를 미리 보고 선택한다. |
| 발행 | 최신 원본, 웹용 자산, 배치와 콘텐츠 연결을 검증하고 공개 개정을 한 번에 전환한다. 웹 변경 중 원본에 반영한 위치 기록은 정리한다. 클릭 연결은 웹에 보존한다. 검토 중 개정이 달라지면 다시 비교하고, 실패 시 직전 공개본으로 계속 서비스한다. |

**예시.** 제작자가 사우나 벽을 붉게 바꾸는 동안 운영자가 의자를 창가로 옮기면, 다음 승인본에는 붉은 벽과 창가 의자가 함께 있다. 의자의 클릭 범위도 따라간다. 제작자도 같은 의자를 무대로 옮겼다면 어느 위치를 쓸지 선택한다. 가구 삭제·ID 중복·인계 식별자 누락은 영향을 받는 대상과 함께 표시하고 발행 전 해결한다. 서로 다른 전체 원본에서 동시에 변경한 외형·재질까지 자동 병합하는 것은 범위 밖이다. 오래된 원본을 바탕으로 한 재업로드는 최신 제작 원본과의 차이를 확인한 뒤 처리한다.

### 가구 복제와 옵션

PC에서 복제하면 현재 외형 옵션을 초기값으로 갖는 새 가구 ID가 생긴다. 모델 종류 ID는 공유하고 위치·회전·크기·옵션값·클릭 영역은 가구별로 저장한다. 편집기는 색상과 해당 가구에 정의된 추가 옵션을 표시한다. 첫 인계에서 옵션의 이름·허용값·대상 재질 슬롯 또는 모델 변형을 정한다. 다른 가구를 편집할 때 공유 재질을 직접 덮어쓰지 않는다. 새 클릭 영역은 복제본에 개별 연결한다.

발행 빌드에서는 기본값 생략과 기본값 명시처럼 결과가 같은 옵션을 정규화한다. 모델 버전·최종 형상·재질 슬롯·텍스처·색상이 같은 가구는 공용 메시·재질을 재사용한다. 클릭 대상과 위치는 별도 ID로 식별한다. 라이트맵과 UV 영역, 투명 정렬 등 그리기 조건까지 호환되면 인스턴싱으로 드로우콜을 줄인다. 색이 달라도 호환되는 형상은 공유할 수 있다. 창가와 방 안의 같은 의자에 서로 다른 베이크 결과가 보존되는지 검증한다.

전체 .blend를 만들 때는 각 복제본을 고유 ID의 편집 가능한 오브젝트로 복원하고 최종 옵션을 Blender 재질·형상에도 적용한다. 재업로드는 인계 당시 가구 목록과 옵션을 기준으로 ID별 생성·유지·삭제를 비교한다. 웹에서 색을 바꾸고 제작자가 위치를 옮긴 경우는 함께 반영하고 같은 옵션을 양쪽이 다르게 바꾼 경우는 선택 후 발행한다.

### 관람과 운영

휴대폰 전체 보기에서 방을 탭하면 확대하고 방 안의 표시를 누르면 개요 카드를 연다. 카드 버튼은 상세 페이지나 외부 링크를 연다. 행사 목록과 상세 URL은 3D 초기화와 독립적으로 제공한다. 드래그를 탭으로 처리하지 않는다. PC에서 권한자가 발행을 요청하면 베이크·검증 성공 후 자동 공개한다. 휴대폰에서는 공개 결과를 확인할 수 있다. 직전 공개본은 모델·라이트맵·매핑·콘텐츠를 한 개정으로 복원할 수 있게 보관하며, 진행 중 인계의 비교 기준도 유지한다.

### 카메라 범위와 웹용 자산

방위각과 내려다보는 각도에 제한을 두고, 전체·방 집중·전환 중·터치 관성에서도 같은 범위를 적용한다. Babylon.js ArcRotateCamera를 후보로 두며 직교 투영에서는 보이는 폭으로 줌을 제어한다. 기존 구도는 방위 약 45°, 수평면 위 고도 약 35°다. 고도를 유지하고 좌우 ±10°로 움직이는 안과 완전 고정안을 비교한다. 수치는 제안값이다. [Babylon.js 카메라](https://doc.babylonjs.com/typedoc/classes/BABYLON.ArcRotateCamera)

고정 구조는 방별로 병합한다. 가구의 편집 루트와 클릭 박스는 보존한다. 안 보이는 면 제거는 웹 파생본에만 적용한다. 모든 허용 각도·줌·화면비·방 전환·관리자 시야에서의 노출과 그림자·반사 기여를 확인한다. **돌릴 수 있는 의자의 뒷면은 기본으로 보존한다.** 관람 화면에는 관리자 편집 코드를 지연 로드하고 클릭 검사는 필요한 영역으로 한정한다. [Babylon.js 장면 최적화](https://doc.babylonjs.com/features/featuresDeepDive/scene/optimize_your_scene/)

### 편집 조명과 모바일 발행

1. **편집.** 웹 편집기는 제작용 장면에서 가져온 고정 광원을 Babylon.js 실시간 조명으로 근사한다. 의자를 옮기면 새 자리의 빛과 그림자를 바로 확인한다. 편집 중에는 기존 공개용 라이트맵을 끄고 초안 배치와 클릭 영역을 함께 갱신한다. 실제 발행본과 색·노출이 얼마나 달라지는지는 사우나와 기도방 기준 구도에서 비교한다. Blender 면광원·월드 조명은 표준 glTF 광원과 별도로 편집기용 정보를 전달한다. [Blender glTF 조명](https://docs.blender.org/manual/en/dev/addons/scene_gltf2.html#lights)
2. **발행 요청.** 서버가 해당 시점의 원본·배치·조명·클릭 매핑·콘텐츠 개정을 고정하고 비동기 작업을 시작한다. 담당자는 창을 닫거나 다음 초안을 편집할 수 있다. 발행 상태는 대기·베이크·최적화 및 검증·공개 완료 또는 실패로 표시한다.
3. **서버 처리.** Blender 작업용 사본에 최종 변환을 적용한 다음 공개 장면에서 정지한 벽·바닥·가구의 빛과 그림자를 라이트맵에 굽는다. 제작 중 옮길 수 있는 의자도 공개 장면에서 정지해 있으면 새 자리의 그림자를 구울 수 있다. 라이트맵 UV와 메시의 대응을 최적화·압축 후 검증하고, Babylon.js 공개 재질에 같은 조명이 두 번 계산되지 않도록 연결한다. 라이트맵 해상도·개수는 휴대폰의 메모리와 초기 로딩 예산에 맞춘다. 전체 .blend 다운로드는 편집 가능한 광원·재질·원본 구조를 보존한다. [Blender 베이크](https://docs.blender.org/manual/en/latest/render/cycles/baking.html)
4. **공개.** 모바일용 모델·라이트맵·클릭 매핑·콘텐츠 검증에 성공한 발행 요청만 한 번에 적용한다. 처리 중·실패 시 기존 공개본을 제공한다. 동일 개정 재시도는 중복 발행을 막고, 더 최근 발행 요청이 있으면 앞선 작업이 늦게 끝나도 그 결과로 되돌리지 않는다. 새 초안 저장 자체는 이미 요청한 개정의 내용을 바꾸지 않는다.
5. **재사용.** 복제본 추가·가구 위치·형상·광원·색상·재질·베이크 설정 변경은 빛에 영향을 받는 자산을 다시 굽는다. 방 사이 영향 범위를 확신할 수 없으면 전체를 굽는다. 행사 본문이나 링크만 바뀌면 같은 렌더 자산을 재사용하고 새 연결을 검증한다.

## Risks / Trade-offs

- 단일 .blend 생성에는 서버 자원이 필요하다. 원본과 결과물은 비공개로 보관하고 권한 있는 사용자에게만 제공한다. 지정 Blender 버전, 격리된 작업 공간, 자동 스크립트 실행 차단, 시간·메모리 제한을 적용하고 작업 실패를 표시한다. [Blender 스크립트 실행](https://docs.blender.org/manual/en/latest/advanced/scripting/security.html)
- 시점 제한만으로 성능이 보장되지는 않는다. 동일 기기·화면 해상도·네트워크·카메라 경로에서 첫 조작 시각, 전환 중 프레임 시간 상위 95백분위, 드로우콜과 다운로드 용량을 비교한다.
- 가구 외형이 크게 바뀌면 ID가 같아도 클릭 박스가 빗나갈 수 있다. 발행 전 박스 겹쳐 보기와 방문자 미리보기를 제공한다.

## Open Questions

| 결정할 항목 | 추천 출발점 |
| --- | --- |
| 카메라 회전·줌·관리자 시점 | 직교 사선, 고도 고정, 좌우 ±10°로 비교. 모바일 세로 화면과 최대 확대에서 클릭하기 어려운 곳을 확인 |
| 모바일 조명 품질 | 고정 조명 베이크를 기준으로 대표 휴대폰에서 라이트맵 해상도·텍스처 메모리·그림자 선명도를 비교 |

| 전체 파일 인계 운영 | Blender 지원 버전·허용 대기 시간과 직전 복원본 외 추가 보관 기간을 정한다. 진행 중 인계에 필요한 비교 기준은 보관 |
| 가구 옵션 목록 | 실제 가구별 색상·추가 옵션과 허용값을 첫 모델 인계에서 정한다 |
