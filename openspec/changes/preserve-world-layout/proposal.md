# Proposal

## Why

제작자가 의자의 외형을 고치는 동안 운영자는 같은 의자를 창가로 옮기고 행사 페이지를 연결할 수 있어야 한다. 두 작업을 합치고 그 결과를 다시 Blender에서 편집하려면 양쪽이 같은 방과 가구를 식별하고 각자 담당한 변경만 반영해야 한다.

## What Changes

- 제작자는 전체 월드에서 움직일 가구와 방의 기준점을 지정한다. 웹용 빌드는 고정 구조를 최적화하면서 편집 단위를 보존한다.
- 운영자는 PC의 Babylon.js 편집기에서 지정 가구를 배치·복제하고 색상과 지원 옵션을 개별 조절한다. 발행 빌드는 같은 모델·옵션의 자원을 공유한다. 운영자는 방이나 가구에 클릭 범위를 추가해 프로젝트 설명·페이지·외부 주소를 연결한다. 모델을 교체하면 새 외형에 기존 배치와 연결을 적용해 미리 본다.
- 제작자는 편집 화면에서 마지막으로 저장한 초안의 배치·복제본·옵션을 담은 전체 .blend 하나를 내려받고 작업을 마친 전체 파일 하나를 다시 올린다. 서버가 독립 변경을 결합하고 충돌을 표시한다.
- 관람 카메라의 사선 각도를 제한하고, 웹 편집 중에는 실시간 광원으로 배치를 확인한다. 발행 요청 후 서버에서 고정 조명을 굽고 휴대폰용 최적화·검증이 끝난 버전을 공개한다.

첫 버전은 휴대폰 우선 관람과 PC 편집을 지원한다. 이동하는 기린과 배회 경로는 후속 범위로 둔다.

## Capabilities

### New Capabilities

- [world-model-handoff](specs/world-model-handoff/spec.md) — 제작자의 파일 인계와 웹용 모델 변환.
- [world-layout](specs/world-layout/spec.md) — 웹 배치, 클릭 연결, 모델 교체와 발행.
- [blender-layout-return](specs/blender-layout-return/spec.md) — 현재 배치가 반영된 전체 월드 파일의 서버 생성·다운로드·재인계.

### Modified Capabilities

## Impact

대상은 [리라지 월드 원본](../../../docs/world/README.md), 향후 웹용 자산 빌드, Babylon.js 관람·관리자 화면, 배치 저장소와 서버의 Blender 변환 작업이다. 행사 페이지의 출처는 [행사 자료](../../../docs/events/README.md)를 따른다. 제작자가 따를 인계 규칙과 운영자가 맡을 일은 [설계안](design.md)에 정리한다.
