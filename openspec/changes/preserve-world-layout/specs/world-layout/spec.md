# Spec Delta

## Purpose

운영자가 지정 가구와 프로젝트 안내를 같은 월드에서 편집하고, 제작자가 외형을 갱신해도 방문자가 의도한 위치에서 올바른 행사 기록을 볼 수 있게 한다.

## ADDED Requirements

### Requirement: 관리자 배치와 모델 교체
웹은 가구 ID와 방 기준 배치를 사용하고 모델 교체 시 인계 후 웹에서만 바꾼 배치와 제작자만 바꾼 배치를 모두 복원해야 한다(MUST). 양쪽 변경의 충돌은 [재인계 명세](../blender-layout-return/spec.md)를 따른다.

#### Scenario: 수정한 의자와 손대지 않은 벤치
- **WHEN** 운영자가 의자를 창가로 옮기고 제작자는 같은 ID의 의자 외형과 벤치의 기본 위치를 수정한다
- **THEN** 새 모델 미리보기에는 새 의자가 창가에, 벤치는 제작자가 정한 새 위치에 보인다

#### Scenario: 방 전체의 이동
- **WHEN** 방 기준점을 방과 함께 이동·회전한 모델을 다시 넣는다
- **THEN** 가구는 저장한 방 내부 위치와 방향을 유지한 채 방과 함께 이동한다

### Requirement: 클릭 영역과 콘텐츠 연결
관리자는 방이나 가구에 상대적인 클릭 영역을 추가·조정하고 새 페이지 또는 기존 페이지를 연결하거나 외부 링크를 지정할 수 있어야 한다(MUST).

#### Scenario: 운영자가 가구를 옮긴 뒤 개요 열기
- **WHEN** 운영자가 의자에 클릭 영역을 붙여 행사 개요와 상세 페이지를 연결하고 의자를 옮겨 발행한다
- **THEN** 방문자가 새 위치의 의자를 누르면 개요가 열리고 연결한 상세 페이지로 이동할 수 있다

#### Scenario: 한 방에 두 개의 안내 추가
- **WHEN** 운영자가 방에 새 영역 두 개를 추가해 하나에는 새 프로젝트 페이지를, 다른 하나에는 외부 주소를 연결한다
- **THEN** 방문자는 각각의 영역에서 지정된 페이지 또는 외부 주소로 이동할 수 있다

### Requirement: 검증된 초안 발행
서버는 쓰기·발행 권한을 확인하고 유효한 모델·배치·클릭 영역·콘텐츠를 같은 공개 버전으로 제공해야 한다(MUST).

#### Scenario: 참조가 깨지는 모델 교체
- **WHEN** 후보 모델에서 매핑 대상이 사라지거나 초안의 페이지 연결이 끊어진다
- **THEN** 관리자는 해당 참조를 확인하고 재연결하거나 제거할 수 있으며 해결하여 발행할 때까지 방문자는 직전 공개 버전을 본다

#### Scenario: 방문자의 수정 시도
- **WHEN** 관리자 권한이 없는 방문자가 배치 저장이나 발행을 요청한다
- **THEN** 서버가 요청을 거부하고 초안과 공개 버전을 보존한다

### Requirement: 제한된 사선 관람
Blender 기준의 따뜻한 흰 바닥과 부드러운 그림자가 있는 월드에서 휠·핀치·버튼으로 0.5~10배 확대·축소할 수 있어야 한다(MUST). 방문자는 대각선 위에서 월드를 관람하며 모든 카메라 조작과 방 전환은 정해진 방위각·고도 범위 안에 있어야 한다(MUST).

#### Scenario: 모바일 회전 한계
- **WHEN** 사용자가 좌우·상하 한계까지 드래그한 뒤 손을 떼거나 방 전환 중 화면 방향을 바꾼다
- **THEN** 카메라가 정해진 범위를 넘거나 월드를 한 바퀴 돌지 않으며 방문자 미리보기에서도 같은 구도가 재현된다

### Requirement: 관람 품질과 최적화 검증
웹용 모델은 합의한 조명 기준과 모바일 성능 목표를 허용 시점에서 확인할 수 있어야 한다(MUST).

#### Scenario: 사우나 방에서 가구 재배치
- **WHEN** 기준 구도와 회전 한계에서 의자를 옮기고 돌려 본다
- **THEN** 의자에 필요한 면과 클릭 영역이 유지되고 이동 전 위치에 의자 그림자가 남지 않으며 사우나의 색·노출을 기준 이미지와 비교할 수 있다

#### Scenario: 대표 모바일 기기에서 방 전환
- **WHEN** 정한 기기·네트워크에서 초기 진입과 전체 보기에서 방으로 들어가는 경로를 재생한다
- **THEN** 첫 조작까지의 시간과 전환 중 프레임 시간을 기록해 합의한 예산 충족 여부를 판단할 수 있다

### Requirement: 실시간 편집과 모바일용 비동기 발행
웹 편집기는 가구 조작을 실시간 광원으로 보여주고, 서버는 발행 요청 시점의 배치에 맞게 구운 고정 조명과 휴대폰용 최적화 결과를 검증한 뒤에만 해당 버전을 공개해야 한다(MUST).

#### Scenario: 비공개로 구운 결과 승인
- **WHEN** 관리자가 구운 결과를 요청하고 검토 화면을 연다
- **THEN** 방문자는 기존 공개본을 보고, 관리자는 같은 방문자 렌더러에서 비공개 모델과 매핑을 확인하며, 승인 시 서버는 그 개정과 동일한 파일을 재베이크 없이 공개한다

#### Scenario: 검토 중 초안 변경이나 복원
- **WHEN** 구운 결과를 준비하거나 검토한 뒤 다른 탭에서 초안을 저장하거나 직전 공개본을 복원한다
- **THEN** 이전 검토의 승인 요청은 거부되며 방문자에게 현재 공개본이 계속 제공된다

#### Scenario: 편집과 발행본의 그림자
- **WHEN** 제작자가 의자를 창가로 옮기고 발행을 요청한다
- **THEN** 제작자는 편집 중 새 위치의 조명을 확인하고, 방문자는 처리 중 기존 월드를 보다가 성공 후 창가의 의자·그림자·클릭 영역이 함께 적용된 월드를 본다

#### Scenario: 처리 도중 다음 초안이나 최신 발행 요청 발생
- **WHEN** 작업 중 새 초안을 저장하거나 뒤에 요청한 발행이 먼저 완료된다
- **THEN** 요청 개정에 이후 초안 내용이 섞이지 않고 오래된 작업이 최신 발행본을 덮어쓰지 않는다

#### Scenario: 베이크 실패
- **WHEN** 라이트맵 생성 또는 최적화 검증이 실패한다
- **THEN** 제작자에게 실패 단계와 재시도를 제공하고 방문자는 직전 공개본을 계속 본다

### Requirement: 기기별 관람과 편집
첫 버전은 휴대폰에서 읽기 전용 관람·결과 확인을 제공하고 편집 기능은 PC에서 제공해야 한다(MUST).

#### Scenario: 휴대폰으로 행사 찾기
- **WHEN** 휴대폰 사용자가 전체 월드의 방을 탭한 뒤 방 안의 표시를 누른다
- **THEN** 방 확대 후 개요 카드가 열리고 버튼으로 상세 페이지나 외부 링크로 이동한다. 3D 로딩 중에도 별도 행사 목록으로 진입할 수 있다.

#### Scenario: 휴대폰의 관리자 접근
- **WHEN** 관리자가 휴대폰에서 월드를 연다
- **THEN** 관람 결과를 확인할 수 있고 배치·옵션·콘텐츠 편집 UI는 제공되지 않는다.

### Requirement: 가구별 독립 편집과 복원
PC 편집기는 지정 가구를 새 ID로 복제하고 각 가구의 배치, 색상과 해당 모델의 추가 옵션을 독립적으로 저장할 수 있어야 한다(MUST).

#### Scenario: 같은 의자 두 개
- **WHEN** 의자를 복제한 뒤 복제본의 색과 추가 옵션을 바꾸고 새 클릭 영역을 연결한다
- **THEN** 원래 의자의 외형과 연결은 유지되고 다시 열어도 복제본만 변경된 옵션과 연결로 표시된다.

#### Scenario: 직전 공개본으로 복원
- **WHEN** 권한자가 직전 공개 개정으로 복원한다
- **THEN** 그 개정의 가구 배치·옵션·조명·클릭 연결과 페이지가 함께 제공된다.
