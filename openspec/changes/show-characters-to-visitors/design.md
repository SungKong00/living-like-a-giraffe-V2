# Design

## Context

공개본 레이아웃은 이미 `characters`와 `defaults.character`를 담고 있다. 편집 장면의 캐릭터 레이어(`web/studio-characters.js`)는 자료실 파일을 관리자 경로에서 읽는다. 관람 장면은 반구광과 방향광을 이미 두고 있어 캐릭터의 PBR 재질은 별도 조명 없이 밝혀진다.

## Decisions

### 공개본별 파일 목록을 처음 조회할 때 고정한다

공개본 ID마다 `characters/published/<ID>.json`에 그 레이아웃이 쓰는 모델(파일·기본 키·잰 키·착용물·보호 여부)과 동작 파일 ID, 대체 모델을 기록한다. 공개 작업은 여러 경로(바로 공개, 검토 후 공개, 이전 공개본 복원)에서 끝나므로, 공개 조회가 그 ID의 목록을 처음 만들 때 고정한다. 공개 직후 관리자가 미리보기로 열면 바로 고정된다. 파일은 내용 해시 이름이고 자료실에서 빼도 지우지 않으므로 고정한 목록은 계속 유효하다. 공개 파일 경로는 현재·이전 공개본의 목록에 든 파일만 내주고 1년 캐시를 허용한다.

대안인 "공개 작업 안에서 고정"은 저장소(`server/store.mjs`)의 공개 경로 세 곳을 모두 바꿔야 해서 택하지 않았다. 공개와 첫 조회 사이에 자료실을 바꾸면 바꾼 값이 고정된다는 한계가 있다.

### 캐릭터 레이어를 편집과 관람이 함께 쓴다

`characterLayer(world, { fileUrl, standIn, onLoad })`가 파일 주소와 자리 표시 여부를 받는다. 관람 장면은 공개 파일 경로를 쓰고 자리 표시를 그리지 않는다. 캐릭터는 고르기 대상(`owners`)에 등록되어, 관람 장면의 클릭이 캐릭터 메시에 닿으면 `onPick`으로 알린다. 연결 페이지가 있으면 페이지를 열고, 없으면 방 선택이 이어진다.

### 움직임 제한

처음에는 `setActive(room)`이 움직일 캐릭터를 정했다. 방을 고르면 그 방의 캐릭터만, 전체 보기에서는 `matchMedia('(pointer: coarse)')`이면 8개, 아니면 24개까지 재생하고 나머지는 첫 프레임에서 멈췄다. 이 제한은 [캐릭터 성능 변경](../scale-character-performance/design.md)에서 없앴다. 지금은 화면에 보이는 캐릭터가 모두 움직이고, 화면에 움직이는 캐릭터가 있을 때만 장면을 계속 그린다.

### 둥근 그림자

캐릭터마다 바닥에 원판 하나를 두고, 가운데가 진하고 가장자리가 투명한 원형 그라데이션 텍스처 하나를 모든 원판이 공유한다. 원판 크기는 모델 기본 키와 크기에 비례한다. 실시간 그림자 지도는 쓰지 않는다.

## Risks / Trade-offs

- 공개와 첫 조회 사이의 자료실 변경이 공개본에 들어갈 수 있다. 운영 흐름상 공개 직후 미리보기를 열기 때문에 받아들인다.
- 캐릭터 PBR 재질은 구운 방과 밝기 기준이 다르다. 반구광·방향광 세기를 캐릭터에 맞추지 않고 지금 값으로 시작한다.
