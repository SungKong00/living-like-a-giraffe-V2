# Design

## Context

스튜디오는 월드 › 방 › 개체 범위 구조와 `PropertyRow`의 `override` 표시를 갖췄다([범위 트리와 덮어쓰기](../redesign-studio-editor/design.md)). 가구는 Blender 원본과 왕복하며 `mergeItems`가 가구 필드를 키 단위로 병합한다. 점토 시안([preview-studio-clay](../preview-studio-clay/design.md))은 벤치·기린 전용 누름 위치로 원본 메시를 변형한다. 관람 모델은 방 단위로 합쳐지고 조명은 Cycles로 굽는다.

## Goals / Non-Goals

**Goals:**

- 월드 기본값과 개체 덮어쓰기를 한 가지 규칙(값이 없으면 위 범위를 따른다)으로 저장하고 표시한다.
- 리깅된 기린 모델과 동작 파일을 웹에서 올리고, 기린마다 동작을 골라 편집 장면에서 재생한다.
- 기존 가구 필드와 Blender 인계 병합을 건드리지 않는다.

**Non-Goals (다음 단계):**

- 관람 화면과 발행 결과에 배치한 기린과 정적 점토 조형을 표시하는 일. 움직이는 기린의 실시간 조명, 점토 변형을 반영한 굽기가 필요하다.
- Blender 인계 파일에 기린과 점토를 싣는 일.
- 기린 이동 경로(배회)와 여러 동작의 전환.

## Decisions

### 덮어쓰기는 위 범위 값이 없는 필드로 표현한다

`defaults.clay.world`·`.objects`·`.giraffes`가 방 형상·가구·기린의 기본 점토이고, `overrides.clay[방·가구·기린 ID]`가 대상별 덮어쓰기다. 하나의 값만 있던 이전 초안은 세 종류 모두에 그 값을 적용한다. 값이 없으면 위 범위를 따른다. 가구 덮어쓰기를 가구 객체 안에 두지 않는 이유는 Blender 왕복 병합이 가구 필드를 키 단위로 비교하기 때문이다. 별도 맵이면 인계 결과에 그대로 남는다. 인계로 가구가 사라지면 서버 검증이 없는 ID의 덮어쓰기를 지운다. 기린은 Blender와 왕복하지 않으므로 `motion`·`speed`를 기린 객체에 두고, 없으면 `defaults.giraffe`를 따른다. `motion: null`은 "정지"로 덮어쓴 상태다.

### 방 형상의 점토

방 전체는 개체 하나보다 훨씬 커서 몇 개의 누름 자리로는 표현되지 않는다. `surfaceField`는 3D 격자 칸마다 엄지 크기 자국 후보를 하나씩 두고, 정점 노멀 방향으로 누른다. 단단한 모서리 양쪽 정점이 함께 움직이도록 같은 위치의 노멀을 평균한다. 바닥 높이 0에서 25cm까지 변위를 0에서 서서히 키워 바닥은 평평하고 가구가 뜨지 않는다. 벽과 바닥은 정점이 거의 없어서, `clay-tessellate.js`가 지정 길이보다 긴 모서리만 나눈다. 모서리 단위로 정하므로 이웃 삼각형이 같은 점에서 나뉘어 틈이 없고, UV·라이트맵 좌표 같은 모든 속성을 보간하며 서브메시 범위를 유지한다. 방 계산은 1~2초 걸리므로 슬라이더를 끄는 동안에는 가구·기린만 갱신하고 놓을 때 방을 갱신한다.

### 점토 변형은 순수 함수 하나로 계산한다

`web/clay-field.js`는 개체 경계 상자와 개체 ID 씨앗으로 누름 위치를 정하고, 결정적 값 노이즈로 굴곡을 만든다. 같은 ID·설정이면 언제나 같은 모양이다. 납작한 개체는 위에서 누르고 키가 큰 개체는 옆에서 누른다. 편집 장면은 가구 사본마다 기하를 분리하고 원래 좌표에서 매번 다시 계산해 변형이 누적되지 않는다. 노멀은 다시 계산한 변화량만 원래 노멀에 더해 모서리 음영을 보존한다. 같은 함수를 이후 발행 단계의 서버 변형에 쓸 수 있도록 DOM·Babylon에 의존하지 않는다.

### 점토 꿈틀거림

월드 공통의 `defaults.clayMotion`에 재생 여부와 강도를 함께 저장한다. 설정이 없는 초안은 꺼짐이다. 빗금 지도는 정적으로 투영한다. 점토 표면 모드는 3차원 노이즈의 기울기로 국소적인 눌림을 초당 다섯 번 갱신한다. v1 화면 모드는 카메라 후처리에서 초당 다섯 번 픽셀을 굴절시킨다. 이전 재생 설정은 같은 강도의 빗금으로 읽는다. 발행한 개정의 설정으로 관람 장면에서도 재생하므로 이 값은 조명 굽기 입력에 포함하지 않는다. 비교 시안은 독립된 값으로 오른쪽 모델에만 움직임을 보여준다.

### 기린 자료실

`<데이터>/giraffes/`에 내용 해시 이름으로 GLB를 저장하고 `library.json`에 목록을 둔다. 모델은 스킨이 하나 이상 있어야 하고 관절 이름 목록을 기록한다. 동작 파일은 애니메이션이 하나 이상 있어야 하고, 모델이 있으면 채널 대상 노드 이름이 모델 관절과 하나 이상 겹쳐야 한다. 동작 참조는 `동작파일ID/클립이름` 문자열이다. 모델을 바꾸면 기존 동작의 일치 여부를 다시 계산해 목록에 표시한다. Blender에서 동작을 만들 때 같은 아마추어에서 액션만 GLB로 내보내면 된다. FBX는 Blender에서 GLB로 변환한다.

### 편집 장면의 기린

모델을 `AssetContainer`로 한 번 읽고 기린마다 `instantiateModelsToScene`으로 뼈대째 복제한다. 동작 파일도 컨테이너로 읽고, 선택한 클립의 `AnimationGroup`을 복제하면서 대상 노드를 이름으로 그 기린의 노드에 연결한다. 업로드 모델이 없으면 리라지 기본 기린을 쓴다. 각 기린의 선택적 `proportions`는 목·머리·다리·몸통의 배율을 보관하며 생략한 값은 1이다. 호환 골격의 각 사본에 동작과 체형을 합성해 의상과 소켓이 함께 따라간다. 기린은 장면에서 눌러 선택하고, 위치는 숫자와 장면 지정으로 바꾼다. 끌기 이동은 가구 끌기와 충돌 처리를 공유해야 하므로 다음 단계로 둔다.

## Risks / Trade-offs

- [편집 장면과 공개본의 차이] → 월드 패널과 기린 패널에 "편집 화면에서만 보입니다"를 표시한다.
- [동작 파일과 모델의 뼈대 이름 불일치] → 업로드할 때 일치 관절 수를 검사하고 하나도 맞지 않으면 거부한다.
- [가구 사본마다 기하를 분리하는 비용] → 점토가 0이면 원래 공유 기하를 그대로 쓰고, 설정이 바뀐 개체만 다시 계산한다.
