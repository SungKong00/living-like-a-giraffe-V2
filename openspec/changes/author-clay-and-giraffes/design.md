# Design

## Context

스튜디오는 월드 › 방 › 개체 범위 구조와 `PropertyRow`의 `override` 표시를 갖췄다([범위 트리와 덮어쓰기](../redesign-studio-editor/design.md)). 가구는 Blender 원본과 왕복하며 `mergeItems`가 가구 필드를 키 단위로 병합한다. 관람 모델은 방 단위로 합쳐지고 조명은 Cycles로 굽는다.

## Goals / Non-Goals

**Goals:**

- 월드 기본값과 개체 덮어쓰기를 한 가지 규칙(값이 없으면 위 범위를 따른다)으로 저장하고 표시한다.
- 리깅된 캐릭터 모델과 동작 파일을 웹에서 올리고, 모델을 골라 캐릭터를 놓고, 캐릭터마다 동작을 골라 편집 장면에서 재생한다.
- 기존 가구 필드와 Blender 인계 병합을 건드리지 않는다.

**Non-Goals (다음 단계):**

- 관람 화면과 발행 결과에 배치한 캐릭터와 정적 점토 조형을 표시하는 일. 움직이는 캐릭터의 실시간 조명, 점토 변형을 반영한 굽기가 필요하다.
- Blender 인계 파일에 캐릭터와 점토를 싣는 일.
- 캐릭터 이동 경로(배회)와 여러 동작의 전환.
- 모델 이름 바꾸기, 모델별 기본 크기·기본 동작.

## Decisions

### 덮어쓰기는 위 범위 값이 없는 필드로 표현한다

`defaults.clay.world`·`.objects`·`.characters`가 방 형상·가구·캐릭터의 기본 점토이고, `overrides.clay[방·가구·캐릭터 ID]`가 대상별 덮어쓰기다. 하나의 값만 있던 이전 초안은 세 종류 모두에 그 값을 적용한다. 값이 없으면 위 범위를 따른다. 가구 덮어쓰기를 가구 객체 안에 두지 않는 이유는 Blender 왕복 병합이 가구 필드를 키 단위로 비교하기 때문이다. 별도 맵이면 인계 결과에 그대로 남는다. 인계로 가구가 사라지면 서버 검증이 없는 ID의 덮어쓰기를 지운다. 캐릭터는 Blender와 왕복하지 않으므로 `model`·`motion`·`speed`를 캐릭터 객체에 두고, `motion`·`speed`가 없으면 `defaults.character`를 따른다. `motion: null`은 "정지"로 덮어쓴 상태다.

### 기린에서 캐릭터로 이름을 바꾼다

기린 외의 모델도 놓을 수 있으므로 편집 대상의 이름을 캐릭터로 한다. 초안 키 `giraffes`·`defaults.giraffe`·`defaults.clay.giraffes`는 `characters`·`defaults.character`·`defaults.clay.characters`가 된다. 서버의 `migrate()`가 이전 키를 새 키로 옮기고, 검증 전과 편집기에 초안을 줄 때 모두 적용한다. 다음 저장부터는 새 키로 남는다. 자료실 폴더 `giraffes/`는 처음 열 때 `characters/`로 이름을 바꾼다. 체형처럼 리라지 기린 골격에만 해당하는 코드는 기린 이름을 유지한다.

### 방 형상의 점토

방 전체는 개체 하나보다 훨씬 커서 몇 개의 누름 자리로는 표현되지 않는다. `surfaceField`는 3D 격자 칸마다 엄지 크기 자국 후보를 하나씩 두고, 정점 노멀 방향으로 누른다. 단단한 모서리 양쪽 정점이 함께 움직이도록 같은 위치의 노멀을 평균한다. 바닥 높이 0에서 25cm까지 변위를 0에서 서서히 키워 바닥은 평평하고 가구가 뜨지 않는다. 벽과 바닥은 정점이 거의 없어서, `clay-tessellate.js`가 지정 길이보다 긴 모서리만 나눈다. 모서리 단위로 정하므로 이웃 삼각형이 같은 점에서 나뉘어 틈이 없고, UV·라이트맵 좌표 같은 모든 속성을 보간하며 서브메시 범위를 유지한다. 방 계산은 1~2초 걸리므로 슬라이더를 끄는 동안에는 가구·캐릭터만 갱신하고 놓을 때 방을 갱신한다.

### 점토 변형은 순수 함수 하나로 계산한다

`web/clay-field.js`는 개체 경계 상자와 개체 ID 씨앗으로 누름 위치를 정하고, 결정적 값 노이즈로 굴곡을 만든다. 같은 ID·설정이면 언제나 같은 모양이다. 납작한 개체는 위에서 누르고 키가 큰 개체는 옆에서 누른다. 편집 장면은 가구 사본마다 기하를 분리하고 원래 좌표에서 매번 다시 계산해 변형이 누적되지 않는다. 노멀은 다시 계산한 변화량만 원래 노멀에 더해 모서리 음영을 보존한다. 같은 함수를 이후 발행 단계의 서버 변형에 쓸 수 있도록 DOM·Babylon에 의존하지 않는다.

### 점토 꿈틀거림

월드 공통의 `defaults.clayMotion`에 재생 여부와 강도를 함께 저장한다. 설정이 없는 초안은 꺼짐이다. 빗금 지도는 정적으로 투영한다. 점토 표면 모드는 3차원 노이즈의 기울기로 국소적인 눌림을 초당 다섯 번 갱신한다. v1 화면 모드는 카메라 후처리에서 초당 다섯 번 픽셀을 굴절시킨다. 이전 재생 설정은 같은 강도의 빗금으로 읽는다. 발행한 개정의 설정으로 관람 장면에서도 재생하므로 이 값은 조명 굽기 입력에 포함하지 않는다.

### 캐릭터 자료실

`<데이터>/characters/`에 내용 해시 이름으로 GLB를 저장하고 `library.json`에 `models`·`motions` 목록을 둔다. 저장소의 `assets-source/characters/riragi-clay/riragi-giraffe-base.glb`는 ID `riragi`인 기본 모델로 항상 맨 앞에 보이고, 그 안의 액션도 기본 동작 파일로 보인다. 둘 다 지울 수 없다. 모델은 스킨이 하나 이상 있어야 하고 관절 이름 목록을 기록한다. 모델에 액션이 있으면 같은 ID의 동작 파일로 함께 등록하고, 모델을 지우면 그 동작 파일도 지운다. 동작 파일은 애니메이션이 하나 이상 있어야 하고, 채널 대상 노드 이름이 어느 모델의 관절과 하나 이상 겹쳐야 한다. 조회 결과의 `matched`는 모델 ID별 일치 관절 수라서, 편집기는 그 캐릭터의 모델과 맞는 동작만 보여준다. 동작 참조는 `파일ID/클립이름` 문자열이다. 모델이 하나뿐이던 이전 `library.json`은 그 모델을 목록에 넣고 `fallback`으로 기록해, 모델을 정하지 않은 이전 캐릭터가 계속 그 모델로 보인다. 그 밖에 모델이 없는 캐릭터는 첫 모델(기본 기린)을 쓴다. Blender에서 동작을 만들 때 같은 아마추어에서 액션만 GLB로 내보내면 된다. FBX는 Blender에서 GLB로 변환한다.

### 모델 ID와 파일을 나눈다

모델 항목은 바뀌지 않는 `id`와 지금 쓰는 파일 `file`(내용 해시)을 따로 갖는다. 처음 올린 모델의 ID는 그 파일 해시와 같아서, `file`이 없던 이전 항목은 `file = id`로 읽으면 그대로 맞는다. **새 버전 올리기**는 같은 ID에 새 파일을 연결하고 이름과 기본 키를 유지하므로, 그 모델로 놓은 캐릭터는 위치·동작·체형을 잃지 않는다. 모델에 들어 있던 액션은 `model`로 그 모델을 가리키는 동작 파일이며, 교체하면 새 파일의 액션으로 바뀐다. 서버가 옛 파일과 새 파일 ID를 돌려주면 스튜디오는 같은 이름의 클립을 쓰던 캐릭터와 월드 기본 동작을 새 파일로 옮긴다. 이 옮김은 되돌리기 한 단계다. 대안인 "교체할 때 파일 해시를 ID로 바꾸고 캐릭터의 `model`을 모두 고쳐 쓰기"는 게시본과 다른 초안에 남은 참조를 고칠 수 없어 택하지 않았다.

모델의 `measured`는 내보낸 그대로의 키(바인드 자세 경계 상자 높이, m)이고 `height`는 크기 100%인 캐릭터가 보일 키다. 처음에는 둘이 같아 기존 캐릭터의 크기가 바뀌지 않는다. 캐릭터의 `scale`은 `height`에 곱하는 배율이므로, 모델의 기본 키를 바꾸면 그 모델의 캐릭터가 모두 따라간다. 기본 모델의 이름과 키는 `library.json`의 `builtin`에 둔다. 기본 모델의 파일은 저장소 원본이라 교체하지 않는다.

초안과 게시본의 캐릭터나 월드 기본값이 쓰는 모델·동작 파일은 자료실에서 뺄 수 없다(409). 되돌리기로 복구할 수 없는 삭제가 쓰는 중인 캐릭터를 망가뜨리지 않도록 하기 위해서다. 뺀 항목의 파일은 데이터 폴더에 남겨, 같은 파일을 다시 올리면 돌아온다. 모델에 딸린 액션은 모델과 함께만 빠진다.

### 편집 장면의 캐릭터

각 모델은 그 모델을 쓰는 캐릭터가 처음 생길 때 `AssetContainer`로 한 번 읽고, 캐릭터마다 `instantiateModelsToScene`으로 뼈대째 복제한다. 읽는 동안과 모델을 열 수 없을 때는 반투명 자리 표시를 그리고, 다 읽으면 그 모델의 캐릭터를 다시 만든다. 동작 파일도 컨테이너로 읽고, 선택한 클립의 `AnimationGroup`을 복제하면서 대상 노드를 이름으로 그 캐릭터의 노드에 연결한다. 각 캐릭터의 선택적 `proportions`는 목·머리·다리·몸통의 배율을 보관하며 생략한 값은 1이다. 리라지 기린과 같은 관절을 가진 사본에만 체형을 합성하고, 다른 모델의 편집기는 체형을 지원하지 않는다고 표시한다. 읽어 둔 모델은 파일 ID로 구분해 교체된 파일을 새로 읽는다. 동작은 캐릭터 ID에서 정한 위치(0~1)부터 반복해, 복제한 캐릭터끼리 같은 순간에 같은 자세를 하지 않는다. 같은 ID는 다시 열어도 같은 위치에서 시작한다.

### 착용물과 얼굴 보호는 모델 파일이 정한다

착용물은 Blender 사용자 속성 `wearable`(glTF extras로 내보냄)이 있거나 이름이 `Wear.`로 시작하는 노드다. 서버가 업로드할 때 ID·이름표·노드 이름을 기록하고, 캐릭터의 `wear`는 켠 착용물 ID 목록이다. 생략하면 아무것도 입지 않아서, 기본 모델을 착용물이 든 파일로 바꿔도 기존 캐릭터의 모습이 그대로다.

얼굴 보호는 정점마다 0~1 값을 갖는 `_CLAY_PROTECT` 속성이다. glTF는 정점 그룹을 싣지 않으므로 `scripts/clay-protect-attribute.py`가 `clay_protect` 정점 그룹을 이 속성으로 옮기고 Attributes를 켜고 내보낸다. Babylon glTF 로더는 사용자 속성을 버리므로 로더 확장(`web/clay-protect-loader.js`)이 같은 이름의 정점 데이터로 읽는다. 점토 조형은 그 값만큼 원래 자리로 되돌리고, 꿈틀거림 셰이더는 속성이 있는 메시에만 정의를 켜서 강도를 줄인다. 대안인 "모델별 보호 높이 슬라이더"는 머리가 위에 있는 서 있는 모델에만 맞아 택하지 않았다. 속성이 없는 모델은 리라지 기린 골격(체형을 지원하는 골격)일 때만 기존 높이 기준을 쓴다.

### 동작 목록

`motion`은 클립 하나(문자열), 여러 개(배열, 최대 8개), 정지(null) 중 하나다. 여러 개면 각 클립을 한 번씩 재생하고, 끝나면 `order`(`sequence`·`random`)에 따라 다음 클립을 시작한다. 클립 사이는 `AnimationGroup` 블렌딩으로 섞는다. 시작 위치는 캐릭터 ID에서 정한 위치를 목록 전체 길이에 나눠 쓴다.

### 놓기와 끌기

추가 메뉴의 캐릭터 구역은 자료실의 모델마다 항목 하나와 **새 모델 올리기…**를 둔다. 모델을 고르면 그 방의 빈 자리(이웃과 1.5m 이상)에 캐릭터를 만들고 놓기 상태로 들어간다. 놓기 상태에서는 캐릭터가 포인터를 따라오고, 클릭하면 그 자리를 저장한다. Esc는 빈 자리에 그대로 둔다. 만든 것과 놓은 것이 각각 되돌리기 한 단계다. 놓을 지점은 메시를 집지 않고 포인터 광선과 방 바닥 평면의 교점으로 구한다. 메시를 집으면 벽 윗면에서 높이만 0으로 내려 캐릭터가 벽 뒤에 숨기 때문이다. 교점이 들어 있는 방이 캐릭터의 방이 된다. 이미 놓은 캐릭터는 가구처럼 장면에서 끌어 옮기고 격자 맞춤을 따른다. 다른 방 위에서 놓으면 그 방으로 옮긴다. 캐릭터는 구운 빛을 받지 않아서 가구 끌기의 조명 갱신이 필요 없다. 방향키·Q·E·⌘D는 가구와 같은 뜻이다.

## Risks / Trade-offs

- [편집 장면과 공개본의 차이] → 월드 패널과 캐릭터 자료실에 "편집 화면에서만 보입니다"를 표시한다.
- [자료실에서 지운 모델을 쓰는 캐릭터] → 지우기 전에 쓰는 캐릭터 수를 알리고, 지운 뒤에는 자리 표시와 다른 모델을 고르라는 안내를 보여준다.
- [동작 파일과 모델의 뼈대 이름 불일치] → 업로드할 때 일치 관절 수를 검사하고 하나도 맞지 않으면 거부한다.
- [가구 사본마다 기하를 분리하는 비용] → 점토가 0이면 원래 공유 기하를 그대로 쓰고, 설정이 바뀐 개체만 다시 계산한다.

### 선택 미리보기와 캐릭터 점토

방·가구·캐릭터의 장면 노드는 개체 종류 등록표에서 찾는다. 상단 미리보기는 그 노드의 실제 메시와 조명을 사용하고, 모델 중심과 배치 회전을 기준으로 별도 카메라를 돌린다. 사용자가 돌린 각도는 미리보기에서만 보관한다. 캐릭터 모델을 다 읽어 자리 표시가 교체되면 같은 선택에서 새 메시로 전환한다.

캐릭터의 정적 변형은 모델의 가장 얇은 축 길이를 단위로 계산한다. 눌림이 겹쳐도 깊이에 상한을 두고 얼굴과 접지면에서 효과를 줄인다. 캐릭터 표면 음영과 빗금은 각 메시의 원본 좌표를 모델 높이에 대한 비율로 변환해 계산한다.

### 두발 점토 기린의 얼굴 체형

양쪽 귀는 귀 뿌리에서 균일하게 키우고, 주둥이는 눈 앞의 전용 관절을 길이 방향으로 늘린다. 같은 골격에 새 걷기 액션을 더할 수 있도록 얼굴 세부 조절과 몸의 FK 포즈를 독립시킨다. 기본 제작 파일은 옷 없이 두 발로 선 자세로 열린다.

클라우드 자료실은 로컬과 같은 모델·골격 검사와 편집 규칙을 쓴다. D1에서 GLB 조각, 골격 이름, 화면 목록을 월드 버전 조건으로 함께 저장한다. 이전 자료실은 처음 편집할 때 기존 GLB에서 골격 이름을 복원한다. 검토 작업은 개정의 모델과 동작 파일 목록을 캡처하고, 공개 파일 경로는 현재·직전 공개 목록만 허용한다.
