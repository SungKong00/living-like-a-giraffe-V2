리라지 v06 원본 팩은 로컬 `assets-source/riragi-v06/`에 둔다. 전체 장면은 `full/riraji_full.blend`에서 열고, 각 방을 따로 볼 때는 `rooms/`를 사용한다. GLB 변형·미리보기·공유 벽에 관한 설명은 원본 팩의 `README_KO.md`를 따른다.

### 점토 기린

[Blender 원본](../../assets-source/characters/riragi-clay/riragi-giraffe.blend)에서 만든 [기본 기린 GLB](../../assets-source/characters/riragi-clay/riragi-giraffe-base.glb)와 [착용 예시 포함 GLB](../../assets-source/characters/riragi-clay/riragi-giraffe.glb)는 같은 골격과 부착점을 쓴다. 발바닥을 원점 높이에 맞췄고, Blender에서 앞은 −Y, 위는 +Z다. 몸통보다 긴 다리와 가는 목의 비율로 옷과 부착점을 맞췄다. 점토 강도를 올리면 몸통과 목을 중심으로 변형되고, 턱에서 위로 갈수록 효과가 줄어 눈·코·입의 위치가 유지된다. 채색과 얕은 손자국 이미지는 원본에 내장되어 있다.

- **포즈**는 `Riragi.Rig`의 포즈 모드에서 편집한다. `Root` 아래에 골반·척추·가슴, 세 마디 목·머리, 양쪽 귀, 네 다리와 두 마디 꼬리가 있다. `LookAround` 액션의 첫 프레임은 기본 자세다.
- **옷**은 기본 자세에서 몸에 맞춘 뒤 몸통의 정점 그룹을 옷에 전송하고 같은 아마추어를 지정한다. `03 • Wardrobe` 컬렉션의 `Wear.Cape`가 예시다. Blender 원본을 열면 착용 예시가 숨겨져 있으며 아웃라이너의 눈 아이콘으로 표시할 수 있다.
- **장식**은 견고하게 고정할 위치에 맞춰 `Socket.Crown`, `Socket.Face`, `Socket.Neck`, `Socket.Chest`, `Socket.Back`, `Socket.Ear.L` 또는 `Socket.Ear.R`를 부모로 지정한다. `Wear.Flower`는 왼쪽 귀에 부착한 예시다.
- **GLB 내보내기**에서는 스킨, 애니메이션, 접선(Tangents), 사용자 속성을 포함하고 아마추어 오브젝트 제거 옵션을 켠다. 스튜디오용 GLB에는 케이프와 꽃핀이 개별 메시로 포함된다. 몸만 내보낼 때는 착용 예시를 숨기고 보이는 오브젝트만 내보낸다.

두발 기린의 Blender 작업 원본은 로컬 `assets-source/characters/riragi-clay/`에 두고, 배포용 GLB는 저장소에서 함께 관리한다. 운영 스튜디오는 등록한 모델·동작을 D1에서 읽고 다음 코드 배포에도 유지한다. 두발 점토 기린은 긴 목, 넓게 접힌 귀와 크림색 주둥이를 가진 옷 없는 기본 캐릭터다. 두발 기린 Blender 원본(`riragi-biped.blend`)을 열면 발굽을 바닥에 붙이고 두 발로 서 있다. `Riragi.Rig`의 **오브젝트 속성 → 사용자 정의 속성**에서 `neck`(목 길이), `body`(몸통 크기), `legs`(다리 길이), `head`(머리 크기), `ears`(귀 크기), `muzzle`(주둥이 길이)을 조절한다. 1.0이 기본값이다. 귀는 뿌리에서 커지고 주둥이는 눈 앞에서 길어진다. 포즈 모드에서 몸통·세 마디 목·팔다리·귀·꼬리를 돌린다. **도프시트 → 액션 에디터**에서 `두 발 걷기`를 선택해 기존 보행을 열거나 새 액션을 만든다. [스튜디오용 모델 GLB](../../assets-source/characters/riragi-clay/riragi-biped.glb)는 같은 골격과 걷기를 쓴다.

두발 기린을 수정한 뒤에는 프로젝트 루트에서 아래 명령으로 스튜디오용 GLB를 다시 만든다. [내보내기 스크립트](../../scripts/export-clay-biped.py)는 피부 가중치와 얼굴 보호 속성을 유지하며 메시를 줄이고, 귀·발목의 색 경계를 보존한다. 양쪽 다리는 보행 중 골반이 오르내리는 높이를 참조해 다리 길이에 따른 접지를 보정한다.

```sh
.venv/bin/python scripts/export-clay-biped.py assets-source/characters/riragi-clay/riragi-biped.blend assets-source/characters/riragi-clay/riragi-biped.glb
```

## Blender 도구

장면을 조사하거나 수정할 때 [프로젝트 Blender 스킬](../../.agents/skills/riragi-blender/SKILL.md)을 사용한다. [Codex 설정](../../.codex/config.toml)은 Blender Lab 공식 MCP 소스를 고정 커밋에서 실행한다. 장면에 연결하려면 Blender 5.1 이상에서 공식 MCP 애드온을 설치하고 브리지를 시작한다. [Blender Lab 설치 안내](https://www.blender.org/lab/mcp-server/)

관람과 편집 화면은 v06 원본의 바닥 오브젝트 `Backdrop`에서 렌더한 조명 이미지를 공유한다. 바닥 조명을 갱신할 때는 초기 원본을 준비한 뒤 프로젝트 루트에서 `.venv/bin/python scripts/render-studio-floor.py`를 실행한다. 방 밑의 부드러운 그림자는 웹에서 현재 방 크기와 위치에 맞춰 근사한다.

## 전체 파일 인계

로컬 스튜디오 상단의 **Blender 인계** 창에서 저장한 초안 또는 현재 공개본을 내려받는다. 지정 장면은 장면 사용자 속성 `riragiWorld`가 참인 장면 한 개다. 서버 작업자는 Blender 4.2.17 Python 모듈로 원본을 다시 연다. 첫 인계 예시는 사우나 방의 ‘서쪽 나무 벤치’다. 부모 아래 좌판 두 단이 있고 바닥과 벽은 방에 남는다.

- 방 기준점에 `roomId`를 두고, 가구의 부모를 해당 방 기준점으로 지정한다. 가구 루트에 `itemId`, 모델 종류 `kind`, 표시 이름 `label`을 둔다. 기존 대상은 ID와 원점·축을 유지한다. Blender에서 새 가구를 복제하면 새 고유 ID를 준다. ID에는 소문자 영문·숫자·하이픈을 쓴다.
- 색과 표면 옵션은 Principled BSDF 재질에서 처리한다. 제작용 색·거칠기 입력을 상수로 사용하는 가구가 대상이다. 웹에서 설정한 옵션 속성과 인계 식별자 `handoff`를 보존한다. 웹의 클릭 영역과 행사 본문은 사이트가 관리한다.
- Blender의 외부 데이터 메뉴에서 텍스처·라이브러리를 패킹하고 저장한 전체 파일을 올린다. 인계 창의 ‘바뀐 점 확인’에서 충돌마다 웹 또는 제작본 값을 고르고 미리보기로 확인한다. 삭제된 가구에 붙은 클릭 영역은 다시 연결하거나 삭제한다. 남은 선택이 없어야 ‘검토 결과를 초안에 적용’이 열리며, 적용한 뒤 발행한다.
- 공개용 사본은 방의 고정 표면과 가구를 나눠 Cycles에서 빛과 색을 굽는다. 불투명 표면의 빛은 부동소수점으로 계산한 뒤 제작 장면의 뷰 변환·룩·노출을 적용해 웹용 sRGB 이미지로 저장한다. 기본 표면은 이 색을 그대로 표시하고, 무광·유광 옵션은 실시간 하이라이트를 더한다. 웹용 사본은 면마다 연결된 재질 출력을 확인한다. 불투명한 면에는 조명을 굽고, 유리와 투과 면은 실시간 재질을 유지한다. 안개·수증기처럼 부피만 지정한 면은 웹 모델에서 제외하며 내려받는 Blender 원본에는 보존한다. 제작자는 내려받은 전체 파일에서 원래 구조·재질로 작업한다.

가구 종류별 허용 색상은 가구 루트의 문자열 속성 `webColors`에 쉼표로 구분해 적는다. 예를 들어 `#226655,#884422`면 두 색과 원본 색을 사용할 수 있다. 기본값 `*`는 모든 색을 허용한다. `webFinishes`에는 허용할 `matte,gloss`를 적는다. 같은 종류의 가구는 같은 옵션 정의를 사용한다.

## 클라우드 스튜디오

[스튜디오](https://living-like-a-giraffe.pages.dev/studio)에서 편집 키로 로그인한다. 팀의 파일과 초안은 Cloudflare에 저장한다. 운영자의 맥이 꺼져 있어도 브라우저에서 파일을 주고받을 수 있다. 검토용 모델 생성과 조명 굽기는 파일을 올린 편집자의 컴퓨터에서 진행한다.

1. **처음 한 번**. 스튜디오의 **Blender 파일**에서 이 컴퓨터용 도우미를 받거나, 바로 옆의 **설치한 도우미 열기**를 누른다. 다른 운영체제용 다운로드는 펼쳐서 선택한다. 연결되면 설치·실행 버튼은 **도우미 연결 및 다운로드** 안에 접히며 필요할 때 다시 펼칠 수 있다. Mac(Apple Silicon)은 ZIP 안의 **Giraffe Studio**를, Windows(x64)는 내려받은 실행 파일을 연다. 도우미가 Blender 실행 환경을 준비하고 로그인 시 자동으로 켤지 묻는다. 완료 안내에서 스튜디오를 열고 브라우저가 이 컴퓨터와의 연결을 요청하면 허용한다.
2. **Blender에서 수정**. **Blender 파일 → 공개본 .blend 내려받기**로 현재 공개 장면을 받아 Blender에서 고친다. 외부 자료를 패킹해 저장한 .blend 하나(최대 16 MiB)를 **수정한 파일 올리기**에 끌어놓는다. 업로드 진행률과 검사 단계가 표시된다.
3. **비공개로 확인**. 웹과 Blender에서 함께 바뀐 항목을 선택하고 **선택한 결과 미리보기 → 검토 결과를 초안에 적용**을 누른다. 적용한 장면에서 웹 편집을 이어갈 수 있다. 행사 글과 클릭 링크는 웹에서 관리한다.
4. **공개**. **발행 → 비공개 미리보기 만들기**를 누르면 도우미가 조명을 굽고 결과를 자동으로 올린다. 작업 중인 컴퓨터에는 전체 베이크 횟수 중 완료된 비율이 표시된다. 최적화와 업로드는 별도 단계로 표시된다. **공개 전 미리보기 → 이 결과 공개**를 누르면 방문자가 새 장면을 본다. **직전 공개본 복원**은 방문자 장면과 내려받는 Blender 파일을 함께 되돌린다.

**캐릭터와 동작**은 월드 패널의 **캐릭터 자료실**에서 각각 GLB로 올린다(클라우드는 파일당 16 MiB). 운동회 기린은 리깅된 모델에 내장된 **두 발 걷기** 한 개를 쓴다. 모델에 든 액션은 업로드할 때 자동 등록되므로 같은 액션을 별도 동작으로 다시 올릴 필요가 없다. 다른 액션은 동작 GLB로 추가한다. 같은 골격에서 보행만 쓸 때는 [동작 전용 GLB](../../assets-source/characters/riragi-clay/riragi-biped-walk.glb)를 사용한다. 모델을 등록한 뒤 **운동회 → 추가**에서 골라 바닥에 놓고, 캐릭터 패널에서 체형과 동작을 바꾼다. 운동회의 두발·네발 고정 모형을 모두 제거한 스튜디오 인계용 월드(`riragi-world-328fc92a-studio.blend`)에는 캐릭터를 따로 배치한다. Blender 조형 작업본(`riragi-world-328fc92a-edit.blend`)에서는 같은 자리에 놓인 리깅 모델을 직접 편집할 수 있다. 배치 미리보기에서는 초안에서 선택한 기린과 동작을 확인할 수 있다. 공개용 모델과 동작 파일은 발행 검토를 시작할 때 고정한다.

자동 시작을 선택한 컴퓨터에서는 다음 로그인부터 스튜디오만 연다. 직접 시작을 선택했거나 다른 브라우저에서 작업하려면 **설치한 도우미 열기**를 누른다. 도우미가 연 기본 브라우저에서 작업한다. 다른 사람이 준비한 작업은 **이 컴퓨터에서 이어서 처리**로 가져온다. 작업은 두 시간 동안 유효하다. 만료된 파일은 다시 올리고, 그사이 공개본이 바뀌면 최신 공개 파일에서 이어서 수정한다.

기존 D1을 버전 기록 지원 코드로 갱신할 때는 배포 전에 `npx wrangler@4 d1 execute giraffe-studio --remote --file=cloud/schema.sql`로 테이블과 인덱스를 추가한다.

운영자는 로컬 초기 데이터에서 `node scripts/seed-cloud.mjs`로 D1 가져오기 파일과 권한이 제한된 `.world/cloud-editor-key`를 생성한다. 초기 가져오기는 새 데이터베이스에 한 번만 한다. `npx wrangler@4 d1 execute giraffe-studio --remote --file=.world/cloud-seed.sql`로 가져온 뒤 `node scripts/backfill-blends.mjs --remote`로 기존 개정의 .blend를 준비한다. Mac의 Xcode 명령줄 도구와 Go 1.23 이상으로 두 도우미를 패키징한다. Go가 PATH에 없으면 `GO_BINARY`에 실행 파일의 절대 경로를 지정한다. `npm run build:cloud`와 `npx wrangler@4 pages deploy dist --branch main`으로 배포한다. GitHub Actions의 `Deploy Cloudflare Pages`는 `main` 푸시 시 macOS에서 같은 빌드를 실행한 뒤 기존 Pages 프로젝트에 배포한다. 저장소 Actions 변수 `CLOUDFLARE_ACCOUNT_ID`와 시크릿 `CLOUDFLARE_API_TOKEN`(해당 계정의 Cloudflare Pages 편집 권한)이 필요하다. 데이터와 비밀 키는 배포 디렉터리 밖에 둔다.

## 스튜디오 편집

상단 **점토 시안**은 v06 사우나 나무 벤치와 네발·두발 점토 기린의 조형을 비교하는 별도 보기다. 왼쪽에 원본, 오른쪽에 선택한 강도가 표시된다. 벤치는 보통, 기린은 약하게로 시작한다. 두 보기는 드래그와 휠로 함께 회전·확대한다. **굴곡 강도**는 윤곽의 휨, **눌림 깊이**는 국소적인 패임, **자국 크기**는 그 폭을 조절한다. 기린에서는 **체형**으로 오른쪽 기린의 목·머리·다리·몸통 비율을 바꾼다. 네발 기린은 **착용**으로 케이프와 꽃핀을 각각 또는 함께 표시한다. 네발 기린은 **두리번거리기**, 두발 기린은 **두 발 걷기**로 양쪽의 움직임을 비교한다. **점토 표면 움직임 → 꿈틀거림**을 켜면 오른쪽 시안에서 **점토 표면**과 **v1 화면 일렁임**을 바꿔 비교할 수 있다. **세부 조절 → 빗금 질감**은 정지한 표면 자국의 강도다. **전체 강도**는 벤치와 기린이 공유한다. 시안 값은 시안 탭을 연 동안 유지되고 월드 초안과 공개본에는 저장되지 않는다.

`/studio`는 왼쪽 목록, 가운데 장면, 오른쪽 속성 패널로 나뉜다. PC에서는 창을 좁혀도 같은 초안이 열리고, 목록과 속성 패널은 장면 아래에 표시된다. 편집은 초안에 자동 저장되고 상단에 저장 상태가 표시된다. 로그인은 8시간 동안 서버를 재시작해도 유지된다. 로그인이 만료되면 상단의 **다시 로그인하고 저장**에서 키를 입력해 열려 있는 편집 내용을 저장한다. 다른 창이 먼저 저장하면 덮어쓰지 않고 다시 열기를 안내한다. 발행하기 전까지 방문자는 공개본을 본다.

**버전 기록.** 상단 실행 취소 옆의 시계 버튼을 열면 현재 초안과 보관한 장면을 함께 살펴볼 수 있다. 현재 초안에서 **이름 붙여 저장**으로 작업에 이름을 남긴다. 서울 기준 하루 첫 편집, Blender 수정본 적용, 버전 복원 직전의 초안은 자동으로 보관한다. 기록을 선택해 장면을 확인한 뒤 **초안으로 복원**하면 해당 Blender 모델과 배치·조명·캐릭터 설정·행사 연결로 편집을 이어간다. 공개는 기존 발행 메뉴에서 한다. 캐릭터 자료실의 모델 설정은 월드와 별도로 공유한다.

- **목록.** 왼쪽 **장면** 탭은 월드 › 방 › 가구 › 클릭 영역 순서의 범위 트리다. 맨 위 **월드**에는 방에 속하지 않은 Blender 조명이, 각 방에는 그 방의 가구·클릭 영역·조명(원본은 `Blender` 표시)이 들어 있다. 이름으로 찾거나 전체·가구·조명·클릭 영역으로 좁힌다. **추가** 메뉴 하나에서 선택한 범위의 방에 가구·조명·클릭 영역·행사 페이지를 만든다.
- **선택과 이동.** 장면에서 가구나 안내 표시를 누르거나 목록에서 고른다. 가구를 끌면 방 바닥을 따라 0.25m 격자에 맞춰 움직이고, 다른 방 위에 놓으면 그 방으로 옮겨진다. Alt를 누른 채 끌면 복제하며 옮기고, ⌘/Ctrl을 누르면 격자 맞춤을 잠시 끈다. 끄는 중 Esc를 누르면 취소된다. 안내 표시도 끌어서 기준 방·가구에 대한 위치를 옮긴다.
- **화면.** 빈 곳을 끌면 화면이 이동하고, 오른쪽 버튼으로 끌면 위·아래·뒤쪽까지 자유롭게 시점을 돌릴 수 있다. 가운데 장면은 휠로 확대하고 F나 목록 선택으로 대상에 맞춘다. 방·가구·캐릭터를 고르면 속성 패널 맨 위에 선택한 모델이 보인다. 미리보기에서 드래그하거나 미리보기에 포커스를 두고 방향키를 누르면 배치 방향을 유지한 채 앞뒤와 위아래를 둘러볼 수 있다.
- **빠른 조작.** 선택한 가구·캐릭터 위의 막대나 단축키로 복제(⌘/Ctrl+D), 15° 회전(Q/E, Shift는 90°), 삭제(Delete)를 한다. 방향키는 화면 방향에 가까운 방 축으로 0.25m(Shift 1m) 옮긴다. 가구를 삭제하면 붙은 클릭 영역도 함께 지워지며 알림의 되돌리기나 ⌘/Ctrl+Z로 복구한다. 장면 아래 보기 도구의 키보드 단추나 **?** 키로 전체 조작법을 볼 수 있다.
- **속성.** 처음 열거나 선택을 해제하면 왼쪽 장면 목록의 **월드**가 선택되고 오른쪽에 월드 설정이 보인다. 목록이나 장면의 빈 곳을 클릭하거나 Esc로 선택을 해제하면 보던 시점이 유지된다. 속성 패널 맨 위의 경로(월드 / 방 / 가구)로 넓은 범위를 바로 연다. **월드**는 모든 방에 공통인 값을 모은 곳이며, 지금은 방 구성과 조명 현황, 수정한 Blender 원본 조명의 일괄 복원을 제공한다. 가구는 이름·방·위치·높이·방향·크기와 종류별 허용 색·표면을 바꾼다. 원본에서 이어받은 값을 바꾼 항목은 라벨이 초록 점으로 표시되고 옆의 되돌리기 단추로 원래 값으로 돌아간다(가구 색·표면은 모델 원본, 원본 조명의 밝기·색·위치·방향은 Blender 원본). 방을 선택하면 그 방의 가구·조명을 보고 가구를 놓거나 클릭 영역을 붙일 수 있다. 클릭 영역은 행사 페이지나 외부 링크에 연결하고, 저장 규칙에 맞지 않는 이름·주소는 입력 칸 아래 이유와 함께 반영되지 않는다.
- **점토.** **월드**에는 점토 기본값이 셋 있다. **점토 · 월드**는 방의 바닥·벽·고정 소품, **점토 · 오브젝트**는 옮길 수 있는 가구, **점토 · 캐릭터**는 배치한 캐릭터에 적용된다. 각각 원본·약하게·보통·강하게 단계를 고르고 **세부 조절**에서 굴곡·눌림 깊이·자국 크기를 바꾼다. 방·가구·캐릭터 편집기의 점토 구역에서 값을 바꾸면 그 방이나 개체만 덮어쓰고, 되돌리기 단추로 기본값을 다시 따른다. 캐릭터는 모델의 가장 얇은 축을 기준으로 굴곡·깊이·자국 크기를 계산한다. 모델 키와 배치 크기를 바꿔도 몸에 대한 자국 비율이 유지되고, 발굽과 얼굴 쪽에서는 눌림이 줄어든다. 방은 엄지 크기 자국을 면 방향으로 누르고 바닥 높이 0은 평평하게 두어 가구가 뜨지 않는다. 긴 면은 모서리를 나눠 정점을 더한 뒤 변형한다. 방 점토는 슬라이더를 놓을 때 적용된다. 지금은 편집 장면에서만 보이고 관람 화면과 굽기에는 반영되지 않는다. 저장 형식은 `defaults.clay.{world,objects,characters}`와 `overrides.clay[방·가구·캐릭터 ID]`다. 기린이라 부르던 때의 `giraffes` 값은 `characters`로 읽는다.
- **점토 표면 움직임.** **월드 → 점토 표면 움직임 → 꿈틀거림**에서 켜고 **전체 강도**로 움직임의 크기를 조절한다. 기본은 꺼짐이고 다시 켜면 직전 강도로 재생된다. 방·가구·기린에 같은 설정을 쓴다. **점토 표면**은 초당 5번 표면 곳곳의 둥근 눌림 음영을 바꾼다. 캐릭터의 요철·빗금 무늬는 모델 키를 기준으로 피부를 따라가며 얼굴에서는 약해진다. **v1 화면 일렁임**은 초당 5번 전체 3D 화면을 최대 1픽셀씩 굴절시킨다. **점토 · 월드 → 세부 조절 → 빗금 질감**은 월드 전체의 정적 질감이다. 이전 버전에서 켜 둔 빗금은 저장한 강도의 정적 질감으로 열린다. 초안에 `defaults.clayMotion`으로 저장되며 발행한 설정은 관람 화면에서도 재생된다. 움직임만 변경하면 기존에 구운 모델을 재사용한다.
- **캐릭터.** 네발과 두발 점토 기린이 기본 모델로 들어 있다. 월드 기본 동작을 정하지 않았으면 두발 기린은 추가할 때부터 걷는다. 선택한 기린의 **모델** 바로 아래 **동작**에서 정지·걷기와 속도를 바꾼다. **추가 → 캐릭터**에서 모델을 고르면 캐릭터가 포인터를 따라오고, 놓을 방의 바닥을 클릭하면 그 자리에 놓인다. Esc를 누르면 빈 자리에 그대로 둔다. 같은 메뉴의 **새 모델 올리기…**로 리깅된 GLB(아마추어와 스킨 포함)를 올리면 그 모델로 바로 하나를 놓는다. 놓은 캐릭터는 장면에서 끌어 옮기고(다른 방으로도), 방향키로 조금씩 옮기고, Q·E로 돌리고, ⌘D로 복제한다. 캐릭터 편집기에서 모델·방·위치·높이·방향·크기(모델 기본 키의 배율, 실제 키를 함께 표시)를 바꾸고 **포인터로 놓기**로 다시 놓는다. 모델이 리라지 기린과 같은 관절 구성이면 **체형**에서 목 길이·머리 크기·다리 길이·몸통 크기를 각각 조절한다. 몸통 크기는 폭·높이·앞뒤 길이와 목 굵기를 함께 바꾸며 케이프도 몸에 맞춰진다. 양쪽 귀 관절이 있으면 귀 크기를, 주둥이 관절이 있으면 주둥이 길이를 추가로 조절한다. 100%가 원래 비율이다. **월드 → 캐릭터 자료실**에서 모델과 동작 파일(GLB, 액션 포함)을 올린다. 모델을 누르면 이름, 기본 키(크기 100%인 캐릭터의 키, 처음에는 파일에서 잰 값), **새 버전 올리기**가 열린다. 새 버전은 배치한 캐릭터의 위치·동작·체형을 그대로 두고 파일만 바꾼다. 초안이나 게시본이 쓰는 모델과 동작 파일은 자료실에서 뺄 수 없고, 뺀 파일은 다시 올리면 돌아온다. Blender에서는 같은 아마추어를 선택하고 동작(액션)을 포함해 glTF 바이너리로 내보낸다. FBX는 Blender에서 GLB로 바꿔 올린다. 서버는 어느 모델과도 뼈 이름이 맞지 않는 동작을 거부하고, 편집기의 동작 목록에는 그 캐릭터의 모델과 맞는 동작만 보인다. **월드 → 캐릭터**에서 기본 동작과 속도를 정하고, 캐릭터마다 동작·속도·점토를 덮어쓴다. 동작을 여러 개(최대 8개) 고르면 차례대로나 무작위로 하나씩 이어 재생한다. 모델에 착용물이 있으면 캐릭터 편집기의 **착용물**에서 하나씩 켠다. 새 캐릭터는 아무것도 입지 않는다. 편집기의 **관람 → 누르면**에서 행사 페이지를 고르면 관람객이 캐릭터를 눌러 그 페이지를 연다. 같은 동작을 쓰는 캐릭터는 캐릭터마다 다른 시점에서 시작한다. 모델을 열 수 없는 캐릭터는 자리 표시로 보이고 편집기가 다른 모델을 고르라고 안내한다. 초안에는 `characters[]`(모델 ID `model`, 기본 모델은 `riragi`)와 `defaults.character`로 저장되고, 올린 파일은 데이터 폴더의 `characters/`에 있고 `library.json`의 모델 항목이 바뀌지 않는 ID와 지금 파일(`file`)을 따로 기록한다. 기린이라 부르던 때의 `giraffes`·`defaults.giraffe`·`giraffes/` 폴더는 처음 읽을 때 새 이름으로 옮긴다. 공개하면 캐릭터가 관람 화면에도 보인다. 방은 구운 빛을 유지하고 캐릭터만 관람 장면의 실시간 빛과 발밑 둥근 그림자를 쓴다. 방을 고르면 그 방의 캐릭터만 움직이고, 전체 보기에서는 터치 기기 8개, 그 밖의 기기 24개까지 움직인다. 공개본이 쓰는 파일 목록은 그 공개본을 처음 조회할 때 `characters/published/<공개본 ID>.json`에 고정되어, 자료실을 바꿔도 다시 공개하기 전까지 관람 화면은 그대로다.
- **캐릭터 모델 만들기.** Blender에서 아마추어와 스킨이 있는 모델을 glTF 바이너리로 내보낸다. 착용물 노드에는 사용자 속성 `wearable`(예: `cape`, 선택으로 이름표 `label`)을 주거나 이름을 `Wear.`로 시작하고, 내보낼 때 **Include → Custom Properties**를 켠다. 점토에 눌리지 않을 눈·입·장식은 `clay_protect` 정점 그룹(가중치 1이면 그대로)으로 칠한 뒤 `.venv/bin/python scripts/clay-protect-attribute.py 경로/모델.blend`를 실행한다. 스크립트가 정점 그룹을 `_CLAY_PROTECT` 속성으로 옮기고 같은 폴더에 GLB를 내보낸다. Blender 안에서 직접 내보낼 때는 텍스트 편집기에서 스크립트를 실행한 뒤 **Data → Mesh → Attributes**를 켠다. 정점 그룹이 없으면 리라지 기린과 같은 골격만 머리 높이로 얼굴을 보호한다.
- **행사 페이지.** 왼쪽 **행사 페이지** 탭에서 추가·수정·삭제한다. 삭제하면 그 페이지에 연결된 클릭 영역도 확인 후 함께 지운다.

## 스튜디오에서 조명 확인과 발행

스튜디오와 **배치 미리보기**는 같은 편집용 모델을 쓴다. 모델을 준비할 때 이동 가능한 가구를 숨기고 방의 조명을 한 번 굽는다. 방마다 바닥 위 1m 높이의 6×6 지점에서 여섯 방향으로 들어오는 빛을 측정한다. 움직이는 가구는 주변 지점의 값을 섞어 사용하고 원본의 색 변환을 적용한다. Babylon의 면광원 조회표는 편집 화면에서 로컬 자산으로 읽는다. 가구를 끄는 동안 중앙 장면과 오른쪽 선택 미리보기 모두 현재 위치의 빛을 반영한다. 방 경계를 넘으면 새 방의 빛을 사용하고 바닥 그림자가 움직인다. 손을 놓으면 초안에 저장한다. 가구 색이 주변 벽에 비치는 효과와 변경한 조명의 간접광은 **발행 → 구운 결과 준비**에서 확인한다. 같은 모델·배치·재질·광원·빌드 방식의 최종 결과는 재사용한다.

방이나 가구를 선택한 뒤 왼쪽 **추가** 메뉴의 조명 구역에서 용도를 고른다. 가구를 선택하면 가구 기준점 위 3m에서 시작한다. 기존 조명은 방 목록이나 장면의 조명 이름을 눌러 다시 편집한다.

| 조명         | 제작 예시                             | 전용 조절                           |
| ------------ | ------------------------------------- | ----------------------------------- |
| 점광원       | 등불처럼 주변 소품을 밝힌다           | 위치·높이                           |
| 스포트라이트 | 벤치나 작품 하나에 빛을 모은다        | 비출 곳, 빔 각도, 가장자리 부드러움 |
| 면광원       | 창이나 조명 패널에서 넓은 빛을 보낸다 | 비출 곳, 직사각형 폭·높이           |

스튜디오에서 전구 표식을 누르면 원본과 추가 조명 모두 같은 방식으로 조작한다. 표식을 끌면 현재 높이에서 수평으로 이동하고, 빨강 X·초록 Y·파랑 Z 화살표를 끌면 해당 축으로 움직인다. 스포트라이트와 면광원은 오른쪽 **배치 → 장면 도구 → 회전**에서 색 고리를 끌어 빛의 방향을 돌린다. 점광원은 사방을 비추므로 이동 화살표만 표시한다. 드래그 중에는 빛이 따라오고 손을 놓으면 초안에 한 번 저장한다. Esc는 현재 드래그를 취소한다.

오른쪽 **빛**에서 색과 출력(W)을 바꾼다. **조명 켜기**로 같은 위치에서 효과를 비교한다. **위치 지정** 후 같은 방의 바닥이나 물체를 클릭하면 높이를 유지하고 수평 위치가 바뀐다. 높이는 Y로 맞춘다. **비출 곳 지정** 후 표면을 클릭하면 빛이 그 지점을 향한다. Esc로 지정을 취소한다. 스튜디오·배치 미리보기는 방 안의 직접광을 실시간으로 보여준다. 추가한 조명이 만드는 최종 그림자, 간접광, 인접한 방에 비치는 빛은 **발행 → 구운 결과 준비**에서 확인한다.

웹에서 추가할 수 있는 조명은 월드당 16개다. 전체 파일 인계 시 점광원은 Blender Point, 스포트라이트는 Spot, 면광원은 직사각 Area로 전달한다. 제작자는 방 기준점 부모와 `webLightId`를 유지해 위치·회전·출력·색·빛 모양을 수정할 수 있다. 렌더 가시성이 웹의 켜짐 상태다. 같은 조명의 빛 모양과 방향을 양쪽에서 수정하면 인계 창에서 어느 쪽 설정을 쓸지 고른다. 왼쪽 **Blender 원본 조명**을 펼치면 장면의 점·스포트·면광원이 Blender 이름으로 나타난다. v06에는 면광원 9개와 스포트라이트 3개가 있다. `Large_softbox`와 `Fill`은 월드 좌표를 쓰며 모든 방의 표면을 지정할 수 있다. 사우나 조명의 좌표와 조준점은 방을 기준으로 한다. 오른쪽에서 밝기·색·켜짐·위치와 방향을 바꿀 수 있고 **원본값 복원**은 선택한 광원만 제작본 값으로 돌린다. 전체 파일에서 원본 조명의 부모·발광면 모양은 유지된다. 제작자는 이름을 바꿔도 `sourceLightId`를 유지하고, 복제한 새 원본 조명에서는 이 속성을 지운다. 웹에서 편집하던 원본 조명을 제작자가 파일에서 삭제하면 인계 창에서 삭제를 확인한다. 태양광, 노드·애니메이션·제약으로 제어하는 광원은 Blender에서 편집한다.

원본 조명을 수정하는 순간부터 편집기는 방의 기존 조명 이미지 대신 표면 고유 색과 원본 광원을 제외해 측정한 환경광을 사용한다. 그 위에 현재 광원으로 직접광을 계산한다. 원형·타원형 면광원은 편집 중 같은 면적의 직사각형으로 근사하며, 새 그림자·반사광·원래 발광면 모양은 비공개 Cycles 굽기에서 확인한다. 방 바깥의 스튜디오 배경 바닥은 별도 이미지다.

실시간 조명과 구운 모델의 화면 렌더링은 관리자 브라우저에서 실행한다. 처음 필요한 굽기와 휴대폰용 최적화는 서버의 Blender 작업자가 처리한다. 중앙에서 확인한 결과는 비공개이며, 공개하려면 상단 **발행**을 사용한다.

1. 가구를 움직이며 클릭 영역을 확인할 때는 상단의 **미리보기**를 연다. 이 화면은 실시간 조명을 사용한다.
2. 공개할 결과를 검토하려면 상단 **발행** 창에서 **구운 결과 준비**를 누른다. 스튜디오가 초안을 저장하고 서버가 해당 개정의 관람 모델을 만든다. 창에 대기·조명 굽기·휴대폰용 최적화 단계가 표시되며, 다른 작업을 하거나 창을 닫았다가 돌아와도 된다.
3. **구운 결과 열기**에서 방과 가구를 확인한 뒤 **이 결과 공개**를 누른다. 창만 닫으면 결과는 비공개로 남는다. 준비 중이거나 검토 중에 초안을 편집하면 그 결과는 취소되고, 발행 창이 다시 준비하라고 알린다.
4. 검토를 생략하려면 발행 창의 **검토 없이 바로 발행**을 선택한다. 서버가 처리를 마치면 요청한 개정이 공개된다. 두 방식 모두 **직전 공개본 복원**으로 이전 모델과 행사 연결을 함께 복원할 수 있다.
